1. Security Gatekeeper Endpoint (/api/caddy/ask):
   - File: internal/server/caddy_ask_handler.go
   - Routes:
     * GET /api/caddy/ask?domain={domain}
     * GET /api/domains/check-ask?domain={domain} (SSOT S5 alias)
     * GET /api/v1/caddy/ask?domain={domain} (v1 API alias)
   - Domain Normalization & Syntax Validation:
     * Trims whitespace and converts domain parameter to lowercase.
     * Enforces RFC 1123 / RFC 952 DNS hostname standards (rejects empty, scheme http/https, port, path, illegal characters, purely numeric TLD).
   - Domain Store Integration:
     * Queries DomainRepository via GetCustomDomainByDomain.
     * Responds HTTP 200 OK only for domains registered with dns_status == 'verified'/'active' or ssl_status == 'active'.
     * Responds HTTP 403 Forbidden for missing, empty, malformed, unregistered, pending, or failed domains.
   - Anti-Abuse Protection:
     * Caddy On-Demand TLS halts certificate issuance when receiving non-2xx status, preventing Let's Encrypt / ZeroSSL rate-limit exhaustion and Denial-of-Wallet attacks.

2. Caddy Dynamic On-Demand TLS & Domain Router Engine (internal/deployer/caddy.go):
   - CaddyRouter Implementation:
     * Supports CaddyConfig.AskURL (default: http://localhost:8080/api/caddy/ask, env: CADDY_ASK_URL) and OnDemandTLS boolean flag.
     * ConfigureOnDemandTLS(ctx, askURL): Dynamically injects TLS automation policy with ask endpoint via Caddy Admin API (/config/apps/tls/automation/on_demand) and writes global Caddyfile snippet fallback.
     * EnsureOnDemandTLS(ctx): Verifies and activates On-Demand TLS policy idempotently.
   - Dynamic Custom Domain Routing:
     * AddCustomDomainRoute(ctx, domain, target): Injects dynamic reverse proxy route mapped to target dial upstream.
     * CustomDomainTarget: Ergonomic abstraction supporting both local sandbox (127.0.0.1:port) and remote BYOS runner (remote_ip:port).
     * Headers: Preserves Host, X-Real-IP, X-Forwarded-For, and X-Forwarded-Proto headers.
     * Graceful Error Handling: Configures custom 503 fallback subroute in errors/routes for booting/restarting backends.
   - Zero-Downtime Unregister & Route Cleanup:
     * RemoveCustomDomainRoute(ctx, domain) / UnregisterCustomDomainRoute(ctx, domain): Revokes Caddy route rule via Admin API DELETE /id/cuan-custom-{domain} instantly without server reload or active connection termination.
     * Cleans up snippet files and in-memory routing registry.
   - Route Duplication Prevention:
     * Re-registering the same custom domain with updated target port or upstream dial safely replaces the existing route via @id without duplicating routes or causing route table bloat.
