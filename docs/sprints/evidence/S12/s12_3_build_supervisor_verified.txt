1. SCRIPT BUILD RUNNER PIPELINE
--------------------------------------------------------------------------------
Implementation Files:
- internal/deployer/script_runner.go
- internal/deployer/script_runner_test.go

Capabilities Verified:
1. Multi-Stack Dependency Installation Pipeline:
   - PHP / Laravel:
     - Detects `composer.json` or `artisan`.
     - Executes isolated package installer:
       `composer install --no-dev --no-interaction --prefer-dist --optimize-autoloader`
   - Node.js / Frameworks (Next.js, React, Express):
     - Detects `package.json`.
     - Executes dependency installer: `npm install --production`
     - Detects build script in package.json or frontend stacks and executes: `npm run build`
   - Python / Django / Flask:
     - Detects `requirements.txt` or `manage.py`.
     - Executes dependency installer: `pip install -r requirements.txt --no-cache-dir`
   - Static HTML:
     - Zero dependency installation needed, validates site files and root entry point.

2. Post-Install Commands Pipeline:
   - Laravel:
     - Auto-generates application key if missing: `php artisan key:generate --force`
     - Runs database migrations: `php artisan migrate --force`
     - Configures symlinks if public directory exists: `php artisan storage:link`
   - Django:
     - Executes migration command: `python manage.py migrate --noinput`
   - Custom Commands:
     - Supports user-defined post-install commands sequence.

3. Timeout Protection, Context Cancellation & Error Handling:
   - Step-level and pipeline-level timeout enforcement via `context.WithTimeout`.
   - Process group isolation (`Setpgid: true`): kills entire child process tree on timeout/cancellation (`syscall.Kill(-pid, SIGKILL)`).
   - Informative error reporting with step name, command string, duration, exit code, and captured stderr.
   - Live stdout/stderr streaming into `LogStreamer` with UTC timestamps.

2. PROCESS SUPERVISOR & DYNAMIC PORT POOL
--------------------------------------------------------------------------------
Implementation Files:
- internal/deployer/port_pool.go
- internal/deployer/supervisor.go
- internal/deployer/supervisor_test.go

Capabilities Verified:
1. Dynamic Port Allocator (Range 9000-9999):
   - Thread-safe, atomic allocation from PortPool (`Allocate(deploymentID)`).
   - Zero collision guarantee through active lease map tracking and TCP socket bind verification (`127.0.0.1:<port>`).
   - Automatic port release on process stop or unexpected crash.

2. Process Lifecycle Management:
   - Launches application runtime with clean process groups (`Setpgid: true`):
     - Laravel: `php artisan serve --host=127.0.0.1 --port=<port>`
     - PHP: `php -S 127.0.0.1:<port> -t <docroot>`
     - Node.js: `npm start` or `node <entrypoint>` with `PORT=<port>`
     - Python: `python3 -m http.server <port>` or `python3 manage.py runserver 127.0.0.1:<port>`
     - Static: `php -S 127.0.0.1:<port> -t <docroot>`
   - State tracking: `running`, `stopped`, `failed`, `crashed`.
   - Background exit watcher: detects child process termination, marks status `crashed`/`failed`, sets health `unhealthy`, releases port back to pool, and records crash error in audit logs.
   - Clean stop & restart: sends SIGTERM to process group, releases/reallocates port, re-runs health check, updates DB record.

3. Caddy Reverse Proxy Driver:
   - Automatic route registration to Caddy reverse proxy:
     - Subdomain: `{slug}.cuan.dojo.cc` -> `127.0.0.1:<port>` via `router.RegisterRoute`.
     - Custom domain: `app.domain.com` -> `127.0.0.1:<port>` via `router.AddCustomDomainRoute`.
   - Clean route revocation on process termination (`router.UnregisterRoute` / `router.RemoveCustomDomainRoute`).

4. Health Check Poller:
   - Synchronous and background polling against `http://127.0.0.1:<port>/` until HTTP 200 response is verified.
   - Configurable retry interval (default 400ms) and bounded timeout (default 20s).
   - Updates `health` in DB (`healthy` vs `unhealthy`) and streams health check milestones.

3. LIVE LOG STREAMING (SSE & WEBSOCKET)
--------------------------------------------------------------------------------
Implementation Files:
- internal/deployer/log_streamer.go
- internal/server/script_deploy_handlers.go
- internal/server/script_deploy_endpoints_test.go

Capabilities Verified:
1. Unified Streamer Architecture:
   - Captures stdout/stderr from both Build Runner Pipeline and Process Supervisor.
   - Maintains in-memory circular ring buffer (default 2000 entries) for instant historical snapshot on connection.
   - Thread-safe non-blocking pub/sub broadcast channel (`Subscribe()`).

2. Dual Real-Time Streaming Modes:
   - Server-Sent Events (SSE):
     - Triggered via `Accept: text/event-stream` or `?stream=true` / `?follow=true`.
     - Sets headers: `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `Connection: keep-alive`.
     - Flushes initial log buffer and pushes new lines as `data: {...}\n\n`.
   - WebSocket (WS):
     - Triggered via standard WebSocket upgrade (`Upgrade: websocket`).
     - Upgrades connection via `gorilla/websocket`.
     - Sends initial snapshot frame `{"type":"init","logs":[...]}` and streams live frames `{"type":"log","entry":{...}}`.
     - Immediate disconnect detection via concurrent client reader goroutine.
   - JSON Snapshot:
     - Returns `{ "logs": [...], "count": N }` for standard REST queries.

4. REST API ENDPOINTS
--------------------------------------------------------------------------------
Implementation Files:
- internal/server/script_deploy_handlers.go
- internal/server/server.go
- internal/server/script_deploy_endpoints_test.go

Endpoints Registered:
- POST /api/v1/projects/{id}/script-deploy & POST /api/projects/{id}/script-deploy
  - Status: 201 Created (or 422 Unprocessable Entity on build failure)
  - Orchestrates: Environment secrets decryption -> Build Runner Pipeline -> Port allocation -> Process spawn -> Caddy route -> Health check -> DB update.
  - Returns ScriptDeploymentDTO, build_result, process (pid, port, domain, status, health), and message.
- GET /api/v1/projects/{id}/script-deploy/logs & GET /api/projects/{id}/script-deploy/logs
  - Status: 200 OK (JSON snapshot / SSE text/event-stream / WebSocket bidirectional stream).
- POST /api/v1/projects/{id}/script-deploy/restart & POST /api/projects/{id}/script-deploy/restart
  - Status: 200 OK
  - Restarts process, re-probes health check, returns updated process status and ScriptDeploymentDTO.
- GET /api/v1/projects/{id}/script-deploy/status & GET /api/projects/{id}/script-deploy/status
  - Status: 200 OK
  - Returns ScriptDeploymentDTO and SupervisedStatus (PID, port, domain, runtime, status, health, uptime_seconds).
