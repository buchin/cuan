1. COMPONENT ARCHITECTURE & IMPLEMENTATION
--------------------------------------------------------------------------------
Implementation Directory: web/src/components/studio/deployer/

Files Created / Updated:
1. `web/src/components/studio/deployer/ScriptDeployerModal.tsx`
   - Multi-step interactive wizard covering complete script onboarding & deployment flow:
     * Step 1: Environment & Secrets:
       - Fetches existing environment configuration via GET /api/v1/projects/{id}/env.
       - Auto-populates variable list with zero plaintext credential leakage (masked secrets).
       - Button 'Auto-Generate Secrets' calls POST /api/v1/projects/{id}/generate-env to generate high-entropy APP_KEY, JWT_SECRET, and SESSION_SALT, automatically saving encrypted vault into data layer.
       - Show/Hide toggle for sensitive secrets.
       - Interactive custom variables manager (add/remove custom key-value pairs).
       - Validation for required variables.
     * Step 2: Database Provisioning & SQL Importer:
       - Engine selection: SQLite (zero-config file database), MySQL (PHP/Laravel standard), PostgreSQL (enterprise high-concurrency).
       - Detection and selection of SQL schema file (`.sql`).
       - Button 'Provision Database' calls POST /api/v1/projects/{id}/provision-db.
       - Visual feedback banner with detailed statistics: database engine, database name, tables count, imported tables list, and total statements executed.
       - Automatically maps generated database credentials back to Step 1 environment variables.
     * Step 3: Target Server & Domain Setup:
       - Selection between subdomain (*.cuan.dojo.cc) and custom domain.
       - Target runtime server selector (Local Docker Sandbox or registered BYOS servers via GET /api/servers).
       - Dynamic non-conflicting port allocation preview.
       - Pipeline runner options (run install, run build assets, run migrations, health check path, timeout).
     * Step 4: Live Build Terminal Console:
       - Triggers POST /api/v1/projects/{id}/script-deploy.
       - Displays real-time streaming logs from WebSocket/SSE streamer.
       - Displays live process supervisor metrics (PID, allocated port, domain, health status).
       - Quick action controls: 'Open Live App', 'Restart Service', 'Tutup Wizard'.

2. `web/src/components/studio/deployer/ScriptDeployerConsole.tsx`
   - Real-time build terminal console powered by `@xterm/xterm`, `FitAddon`, and `WebLinksAddon`.
   - Dual-mode streaming connection:
     * WebSocket connection to /api/v1/projects/{id}/script-deploy/logs.
     * Automatic fallback to Server-Sent Events (GET /api/v1/projects/{id}/script-deploy/logs?stream=true).
     * Graceful fallback to REST snapshot polling (limit=100) if WS/SSE are unavailable.
   - Ring buffer capped at 1,000 log lines with proper unmount listeners preventing memory leaks.
   - Formatted ANSI output for STDOUT (green), STDERR (red), and SYSTEM (cyan) streams with UTC timestamps.
   - Console toolbar: connection status badge, live status badge (Building, Running, Healthy HTTP 200, Failed), Clear logs, Copy logs to clipboard, and 'Open Live App' button.

3. `web/src/components/studio/deployer/ScriptDeployerControls.tsx`
   - Quick Controls & Status Badges embedded in Kanban Board header (`ProjectTasksBoard.tsx`):
     * Status Badges:
       - Building: Amber pulsating badge with spinning indicator.
       - Healthy: Emerald green badge with live ping animation (HTTP 200 OK).
       - Running: Blue running badge.
       - Unhealthy: Amber alert badge.
       - Stopped: Slate badge.
       - Failed: Rose red failure badge.
     * Quick Action Buttons:
       - 'Deploy Script': Opens ScriptDeployerModal wizard directly.
       - 'Open Live App': Opens the live release URL in a new tab when running/healthy.
       - 'View Logs': Jumps directly to Step 4 Live Build Console in ScriptDeployerModal.
       - 'Restart Service': Triggers POST /api/v1/projects/{id}/script-deploy/restart with instant toast feedback.
     * Background Poller: Periodically polls GET /api/v1/projects/{id}/script-deploy/status every 8 seconds.
