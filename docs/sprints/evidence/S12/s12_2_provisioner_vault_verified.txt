1. AUTOMATED DATABASE PROVISIONER ENGINE & SQL SCHEMA IMPORTER
--------------------------------------------------------------------------------
Implementation Files:
- internal/deployer/provisioner.go
- internal/deployer/provisioner_test.go

Capabilities Verified:
1. Multi-Engine Isolated Provisioning:
   - SQLite:
     - Automatically creates isolated directory `data/projects/{id}/data/`.
     - Initializes SQLite database file `<db_name>.sqlite` using pure Go modernc.org/sqlite.
     - Tests database connection and writability via PingContext.
   - PostgreSQL:
     - Validates database and username safety against SQL injection (alphanumeric + underscore only).
     - Connects via pgx/v5 stdlib driver to execute DDL:
       CREATE DATABASE "<db_name>";
       CREATE USER "<db_user>" WITH ENCRYPTED PASSWORD '<db_password>';
       GRANT ALL PRIVILEGES ON DATABASE "<db_name>" TO "<db_user>";
     - Automatically cleans up database if user creation fails.
   - MySQL:
     - Validates database and user identifiers against injection.
     - Connects via go-sql-driver/mysql to execute DDL:
       CREATE DATABASE IF NOT EXISTS `<db_name>` CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
       CREATE USER IF NOT EXISTS '<db_user>'@'%' IDENTIFIED BY '<db_password>';
       GRANT ALL PRIVILEGES ON `<db_name>`.* TO '<db_user>'@'%';
       FLUSH PRIVILEGES;

2. SQL Schema Parser & Executor:
   - ParseSQLStatements splits SQL content into separate executable statements.
   - Respects line comments (-- and #), multiline block comments (/* ... */), single-quoted strings ('...'), double-quoted strings ("..."), and backticks (`...`).
   - Semicolons inside quotes, string literals, or comments do not cause premature statement splitting.
   - Transactional execution: For SQLite and PostgreSQL, statements execute within a transaction; upon any error, rollback is automatically performed with 0 residual tables.
   - Post-import table querying and row count verification:
     - SQLite: SELECT name FROM sqlite_master WHERE type='table' AND name NOT LIKE 'sqlite_%';
     - PostgreSQL: SELECT table_name FROM information_schema.tables WHERE table_schema='public';
     - MySQL: SHOW TABLES;

3. Credentials Encryption & Data Layer:
   - Database passwords encrypted via AES-256-GCM using internal/crypto.
   - Stored in table provisioned_databases (db_password_encrypted).
   - Zero plain password leakage: ToDTO() returns ProvisionedDatabaseDTO with has_password: true and no plaintext password.

2. ENVIRONMENT SECRETS GENERATOR & ENV MERGER
--------------------------------------------------------------------------------
Implementation Files:
- internal/deployer/env_generator.go
- internal/deployer/env_generator_test.go
- internal/inspector/env_merger.go

Capabilities Verified:
1. Application Secrets Generation:
   - Laravel APP_KEY: 32 cryptographically secure random bytes encoded as base64 with prefix "base64:".
   - JWT Secret: 256-bit (32 bytes) hex-encoded secret key (64 hex characters).
   - Session Salt: 16-byte (128-bit) hex-encoded salt string (32 hex characters).
   - Secure Passwords: High-entropy passwords containing lowercase, uppercase, digits, and symbols.

2. Database Variables Auto-Mapping:
   - SQLite: DB_CONNECTION=sqlite, DB_DATABASE=<path>, DB_HOST=127.0.0.1, empty user/pass.
   - MySQL: DB_CONNECTION=mysql, DB_HOST=<host>, DB_PORT=3306, DB_DATABASE, DB_USERNAME, DB_PASSWORD.
   - PostgreSQL: DB_CONNECTION=pgsql, DB_HOST=<host>, DB_PORT=5432, DB_DATABASE, DB_USERNAME, DB_PASSWORD.

3. Template .env Merging:
   - Reads project's .env.example / .env.sample / template.
   - Preserves comments (#, //), empty lines, and original formatting.
   - Replaces placeholder keys (e.g. APP_KEY, DB_DATABASE, DB_PASSWORD) with generated/mapped values.
   - Appends any new variables not present in the original template.
   - Writes merged .env to project's directory on disk.

4. Zero Credential Leakage & Masking:
   - MaskEnvVars and MaskRawEnv detect sensitive keys (PASSWORD, SECRET, KEY, TOKEN, SALT, AUTH, PASS, CREDENTIAL).
   - Values masked as "base64:********************" or "********".
   - Never logs or exposes plaintext secrets in API JSON responses.
   - Persists encrypted .env to script_deployments (env_encrypted) via AES-256-GCM.
