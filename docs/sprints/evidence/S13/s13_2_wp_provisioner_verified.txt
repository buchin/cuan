1. SCOPE & IMPLEMENTATION DETAILS
--------------------------------------------------------------------------------
Component Architecture & Implementation Files:
1. internal/wordpress/installer.go:
   - WordPress Orchestrator and Installer Engine implementing turnkey deployment pipeline.
   - Dynamic port allocation integration via PortPool (range 9000-9999).
   - Integration with DatabaseProvisioner for isolated MySQL database creation.
   - Core cache resolution and extraction into deployments/wordpress/{deployment_id}.
   - Automated wp-config.php generation with 8 cryptographically secure random salts.
   - Automated headless setup and schema initialization with permalinks /%postname%/.
   - Process supervision of PHP built-in runtime server (php -S 127.0.0.1:{port}).
   - Dynamic Caddy reverse proxy route registration with Auto-SSL / TLS on-demand.
   - Health check poller verifying HTTP 200 response on public home (/) and /wp-login.php.
   - Database layer persistence with AES-256-GCM encrypted admin and database passwords.
   - Complete lifecycle methods: Deploy, GetDeployment, RestartDeployment, StopDeployment, HealthCheck, DeleteDeployment.

2. internal/wordpress/config_generator.go:
   - Cryptographically secure random 64-character salt key generation via crypto/rand.
   - Generates 8 distinct WordPress salt constants:
     AUTH_KEY, SECURE_AUTH_KEY, LOGGED_IN_KEY, NONCE_KEY,
     AUTH_SALT, SECURE_AUTH_SALT, LOGGED_IN_SALT, NONCE_SALT.
   - Safe character set: letters, digits, and punctuation (excluding single quotes and backslashes).
   - Reverse proxy header detection: $_SERVER['HTTP_X_FORWARDED_PROTO'] === 'https'.
   - Custom table prefix support (default wp_).
   - Atomic disk write of wp-config.php with file permission 0644.

3. internal/wordpress/cache.go:
   - WordPress core archive caching and download engine.
   - Safe extraction engine for .tar.gz and .zip archives.
   - Strict ZipSlip vulnerability mitigation ensuring all archive entry paths remain inside destination directory.
   - Strips root wordpress/ directory component so extracted files sit directly in the deployment directory.
   - CreateMockWordPressCore utility for deterministic offline sandbox execution.

4. internal/wordpress/bootstrap.go:
   - Headless automated WordPress setup and bootstrapping engine.
   - Dual execution model:
     a) WP-CLI automation (wp core install and wp rewrite structure /%postname%/).
     b) Headless PHP script runner (cuan-bootstrap.php) invoking wp_install() and update_option().
     c) Headless simulation for offline/mock environments.
   - Persists execution state in .cuan-bootstrapped.json.

5. internal/wordpress/health.go:
   - Health check probe engine querying both http://127.0.0.1:{port}/ and http://127.0.0.1:{port}/wp-login.php.
   - Verifies HTTP 200 OK responses with latency tracking.
   - Retries with backoff and configurable timeouts.

6. internal/server/wordpress_handlers.go & internal/server/server.go:
   - HTTP API endpoints wired into Cuan Studio:
     - POST   /api/projects/{id}/wordpress/deploy      (and /api/v1/projects/{id}/wordpress/deploy)
     - GET    /api/projects/{id}/wordpress             (and /api/v1/projects/{id}/wordpress)
     - POST   /api/projects/{id}/wordpress/restart     (and /api/v1/projects/{id}/wordpress/restart)
     - GET    /api/projects/{id}/wordpress/health      (and /api/v1/projects/{id}/wordpress/health)
     - POST   /api/projects/{id}/wordpress/stop        (and /api/v1/projects/{id}/wordpress/stop)
     - DELETE /api/projects/{id}/wordpress             (and /api/v1/projects/{id}/wordpress)
   - Zero credential leakage on public API endpoints (DTO returns masked passwords).
