1. Centralized Rollup Aggregator Engine (internal/campaign/aggregator.go):
   - Package: internal/campaign
   - Source File: internal/campaign/aggregator.go
   - Model & Metrik:
     * RollupMetrics:
       - campaign_id & batch_id (UUID string)
       - total_target & total_tasks (jumlah target subtask proyek)
       - pending_tasks (subtasks berstatus backlog, pending, draft, queued, todo)
       - running_tasks (subtasks berstatus doing, running, in_progress)
       - completed_tasks (subtasks berstatus done, completed, success)
       - review_tasks (subtasks berstatus review, in_review)
       - failed_tasks (subtasks berstatus failed, blocked, error)
       - success_percentage (persentase penyelesaian 0.0% – 100.0% dibulatkan 2 desimal)
       - status ("draft", "pending", "running", "completed", "failed", "review")
       - updated_at (timestamptz UTC)
   - Kemampuan Komputasi & Aggregasi:
     * Akurasi 100% & Parent Epic Filtering:
       Secara otomatis memisahkan child subtasks proyek dari parent epic task bila keduanya tercatat dalam satu batch_id, sehingga penghitungan metrik total_target dan persentase sukses mencerminkan target aktual tanpa bias.
     * Standardisasi Status Terpadu (ClassifyTaskStatus):
       Mengklasifikasikan ragam status task menjadi 5 bucket agregat secara konsisten dan aman.
     * Pemutakhiran Cepat In-Memory & Repository Refresh:
       - UpdateRollupInMemory: Cache thread-safe berbasis sync.RWMutex untuk update instan tanpa membebani IO database.
       - RefreshFromRepository: Membaca status mutakhir dari ProjectStudioRepository (berdasarkan batch_id atau parent_task_id) untuk sinkronisasi state.
   - Runner Lifecycle Listeners:
     * OnCampaignStart(campaignID, tasks):
       Mendaftarkan seluruh subtask secara instan saat runner mulai dipicu (status awal: pending/backlog).
     * OnTaskStart(task):
       Memperbarui status subtask menjadi 'doing', menghitung ulang rollup, dan memancarkan event 'task.status_changed' serta 'campaign.progress'.
     * OnTaskComplete(task, result):
       Memperbarui status subtask menjadi 'done', meningkatkan completed_tasks, menghitung ulang success_percentage, dan memancarkan event 'task.status_changed' serta 'campaign.progress'.
     * OnTaskFail(task, err):
       Memperbarui status subtask menjadi 'failed', meningkatkan failed_tasks, dan memancarkan event 'task.status_changed' serta 'campaign.progress'.
     * OnCampaignComplete(campaignID, result):
       Menentukan status akhir kampanye ('completed' atau 'failed') dan memancarkan event 'campaign.completed' serta 'campaign.progress'.

2. Real-Time Server-Sent Events (SSE) Streaming Engine & Endpoints:
   - Handler File: internal/server/campaign_handlers.go
   - Integrasi Server: internal/server/server.go
   - Endpoints Terpasang:
     * GET /api/campaigns/{id}/events & GET /api/v1/campaigns/{id}/events (HTTP 200 text/event-stream):
       Endpoint real-time SSE stream untuk browser client / UI.
     * GET /api/campaigns/{id}/rollup & GET /api/v1/campaigns/{id}/rollup (HTTP 200 OK):
       Endpoint REST cepat untuk inspeksi metrik agregat tanpa membuka koneksi streaming.
   - Header Standar SSE:
     * Content-Type: text/event-stream
     * Cache-Control: no-cache
     * Connection: keep-alive
     * X-Accel-Buffering: no
     * Access-Control-Allow-Origin: *
   - Format Event Terpancar:
     * connected: Handshake awal saat client tersambung ({"status":"connected","campaign_id":"..."}).
     * campaign.progress: Snapshot RollupMetrics mutakhir dikirim saat koneksi awal dan setiap kali terjadi perubahan state subtask.
     * task.status_changed: Detail transisi status subtask individual (task_id, project_id, title, old_status, new_status, timestamp).
     * campaign.completed: Sinyal finalisasi kampanye batch lengkap dengan status akhir dan ringkasan eksekusi.
   - Heartbeat & Graceful Cleanup (Zero Memory Leak):
     * Heartbeat Interval 15 Detik:
       Secara periodik memancarkan komentar SSE ": ping\n\n" untuk menjaga koneksi tetap hidup melewati reverse proxy Nginx/Caddy/Cloudflare tanpa idle timeout.
     * Graceful Cleanup:
       Mendeteksi pemutusan koneksi client via r.Context().Done(), menghentikan heartbeat ticker, menghapus subscription dari broker map, dan menutup channel buffer subscriber. Terverifikasi SubscriberCount kembali ke 0 tanpa leak memory.
