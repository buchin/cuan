1. PROJECT ARCHIVING (BACKEND ENDPOINTS & DATABASE LAYER)
--------------------------------------------------------------------------------
Target Files:
  - internal/db/project.go
  - internal/project/service.go
  - internal/server/server.go
  - internal/server/project_archive_handlers_test.go

A. Database Schema & Repository Methods:
  - Table: `projects` (PostgreSQL column `is_archived BOOLEAN NOT NULL DEFAULT FALSE`).
  - Interface `ProjectRepository` updated with:
      ArchiveProject(ctx context.Context, id string) error
      UnarchiveProject(ctx context.Context, id string) error
  - Implemented in `SQLProjectRepository` and thread-safe `MemoryProjectRepository`.

B. Service & API Endpoints:
  - `PATCH /api/v1/projects/{id}/archive` (and `/api/projects/{id}/archive`):
    - Sets project `is_archived = true`, `status = 'archived'`.
    - Returns 200 OK with `{"status":"archived","project_id":id}`.
  - `PATCH /api/v1/projects/{id}/unarchive` (and `/restore` alias):
    - Sets project `is_archived = false`, `status = 'active'`.
    - Returns 200 OK with `{"status":"active","project_id":id}`.
  - `GET /api/v1/projects` Query Filtering:
    - Default behavior: Returns only active projects (`is_archived = FALSE`).
    - Query `?archived=true`: Returns only archived projects (`is_archived = TRUE`).
    - Query `?include_archived=true`: Returns all projects (both active and archived).
