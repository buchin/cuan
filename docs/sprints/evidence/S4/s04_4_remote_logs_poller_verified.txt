1. Remote Log Streamer (internal/deployer/remote_streamer.go):
   - Streaming stdout/stderr proses aplikasi remote secara asinkron over SSH channel:
     * Menjalankan stream reader yang membaca file log remote (`~/cuan-apps/<id>/app.log`) via command tail streaming (`touch <file> && tail -n +1 -f <file>`) pada host remote.
     * Menginjeksi baris log secara real-time ke in-memory ring buffer (`LogStreamer`) berkapasitas dinamis (default 1000 baris) dan mempersistensikan setiap baris ke database PostgreSQL tabel `deployment_logs`.
     * Mendukung snapshot reading langsung (`FetchSnapshot` / `FetchRemoteLogs`) untuk menangani skenario recovery atau sinkronisasi log instan.
     * Auto-reconnect resilient: Jika koneksi SSH terputus sesaat, loop tailer secara otomatis melakukan reconnect dengan exponential backoff dan melanjutkan streaming (`tail -n 0 -f`) tanpa menghasilkan baris log duplikat.
     * Bersih tanpa leak: Menggunakan context cancellation dan scanner termination channel sehingga ketika `Stop()` dipanggil, seluruh session SSH dan goroutine tertutup dengan sempurna tanpa hanging.

2. Background Process Health Poller (internal/deployer/health_poller.go):
   - Monitoring periodik status kesehatan proses remote:
     * Menjalankan inspeksi liveness periodik (`PollOnce` atau background loop dengan interval configurable, default 5s) untuk semua remote deployment berstatus `running`.
     * Mengeksekusi script probe cerdas `# cuan-health-poll` pada remote VPS yang mengecek PID file (`~/cuan-apps/<id>/app.pid`) dan status proses melalui sinyal OS `kill -0 <pid>`.
     * Deteksi Crash Akurat: Jika `app.pid` masih ada tetapi proses `kill -0` mati di luar kendali Cuan, poller mendeteksi status `CRASHED`, memperbarui status deployment di Store menjadi `crashed`, me-reset `process_pid = 0`, melepaskan port yang dialokasikan dari `PortPool`, mencatat system audit log di database, dan memicu callback `onStateChange`.
     * Deteksi Stopped: Jika proses telah berhenti dan `app.pid` bersih, poller menandai status `stopped` dan melepaskan port.
     * Resilient Network Disconnect Handling: Jika terjadi network blip, handshake timeout, atau server unreachable sesaat, poller TIDAK menandai deployment sebagai crashed. Poller mencatat kegagalan transien, menjadwalkan auto-reconnect, me-refresh koneksi SSH yang stale di pool, dan menyambung kembali saat jaringan pulih tanpa goroutine leak.

3. Integrasi Transparent Control Plane & API Handlers:
   - Driver Factory & RemoteSSHDriver:
     * `RemoteSSHDriver.Start` secara otomatis menyalakan `RemoteLogStreamer` di background.
     * `RemoteSSHDriver.Stop` dan `Delete` secara bersih menghentikan log streamer terkait.
     * `RemoteSSHDriver.GetStreamer(id)` dan `DriverFactory.GetStreamer(id)` menyediakan akses transparan ke active in-memory ring buffer.
     * `RemoteSSHDriver.GetLogs(ctx, id, limit)` melayani log dari database Store, in-memory ring buffer, atau snapshot remote fallback secara konsisten dengan `LocalDriver`.
   - HTTP Handlers (`internal/server/deployer_handlers.go`):
     * Endpoint `/api/deployments/{id}/logs` melayani permintaan standar JSON array secara transparan baik untuk deployment lokal maupun remote.
     * Mode Server-Sent Events (SSE) (`stream=true` atau `Accept: text/event-stream`) memanfaatkan subscriber channel `streamer.Subscribe()` untuk push log instan ke client browser dengan fallback ticker periodik.
   - Server Lifecycle (`cmd/server/main.go` & `internal/server/server.go`):
     * `ProcessHealthPoller` terpasang di `Server` dan dinyalakan pada boot daemon serta dihentikan secara graceful pada SIGTERM/SIGINT.
