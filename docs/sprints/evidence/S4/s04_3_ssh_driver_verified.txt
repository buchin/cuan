1. Implementasi Struct RemoteSSHDriver (Kontrak Penuh DeployDriver):
   - File: internal/deployer/ssh_driver.go
   - Mematuhi seluruh kontrak interface `DeployDriver`:
     * Deploy(ctx, req): Mentransfer bundle aplikasi via tar over SSH stream langsung ke remote path terisolasi `~/cuan-apps/<deployment_id>/`. Menjalankan auto-detection runtime (PHP, NodeJS, Static, Custom) berdasarkan isi arsip, menetapkan domain Caddy virtual host, dan menyimpan metadata deployment ke Store dengan server_id terasosiasi.
     * Start(ctx, id): Mengalokasikan dynamic port lease (9000-9999) via PortPool, mendekripsi private key via KeyVault, menghubungkan SSH via SSHManager/ClientPool, mengeksekusi runner aplikasi di background host remote via `nohup env PORT=... <cmd> > app.log 2>&1 & echo $! > app.pid`, membaca PID remote, memperbarui status DB ke 'running', dan mendaftarkan dynamic route ke Caddy router.
     * Stop(ctx, id): Menghentikan proses remote secara graceful: mengirim SIGTERM (kill -15), melakukan polling liveness hingga 2 detik, mengeksekusi force SIGKILL (kill -9) jika timeout, membersihkan `app.pid`, melepaskan port lease dari PortPool, mencabut route Caddy, dan mengupdate status DB ke 'stopped' serta process_pid ke 0.
     * Restart(ctx, id): Menjalankan Stop secara graceful lalu mengeksekusi Start ulang pada remote host.
     * Health(ctx, id): Melakukan verifikasi runtime remote melalui PID probe `kill -0 <pid>` over SSH channel dan connectivity test pada port remote yang dialokasikan.
     * GetLogs(ctx, id, limit): Mengambil log terbaru dari Store.
     * List(ctx) & Get(ctx, id): Mengambil record deployment dari persistent Store.
     * Delete(ctx, id): Menghentikan proses remote, menghapus direktori terisolasi `rm -rf ~/cuan-apps/<id>` di remote VPS, mencabut route Caddy, membersihkan cache lokal jika ada, dan menghapus record deployment dari Store.

2. Remote Path Traversal Defense:
   - File: internal/deployer/ssh_driver.go
   - `ValidateDeploymentID`: Memvalidasi format ID aplikasi remote dengan whitelist alphanumeric, dash, dan underscore (`^[a-zA-Z0-9_-]+$`). Menolak keras token traversal `..`, slashes `/`, backslashes `\`, control chars, null bytes, dan shell metacharacters untuk mencegah path traversal dan command injection.
   - `ValidateRemotePath`: Memastikan seluruh path operasi file terkurung secara absolut di dalam `cuan-apps/<deployment_id>/` dan mengembalikan `ErrRemotePathTraversal` jika terdapat traversal escaping (`../../etc/passwd`, dsb).
   - `StreamZipAsTarToSSH`: Melakukan inspeksi ketat anti-ZipSlip sebelum streaming ke host remote, menolak arsip yang mengandung relative escaping atau absolute path.

3. Driver Factory & Deployer Engine Routing:
   - File: internal/deployer/driver_factory.go
   - Struct `DriverFactory` mematuhi interface `DeployDriver`:
     * Jika `server_id` kosong/null -> Mendelegasikan seluruh eksekusi ke `LocalDriver` (menjaga kompatibilitas 100% dan zero regression untuk deployment Sprint 3).
     * Jika `server_id` terisi -> Mendelegasikan eksekusi ke `RemoteSSHDriver` (Sprint 4 BYOS).
     * `DriverFor(ctx, id)`: Secara dinamis membaca deployment record di Store untuk merouting `Start`, `Stop`, `Restart`, `Health`, `Delete` ke driver yang sesuai.
   - Integrasi Control Plane:
     * File: internal/server/server.go: Server deployerDriver diinisialisasi menggunakan `NewDriverFactory(localDriver, remoteDriver, depStore)`.
     * File: internal/server/deployer_handlers.go: Mendukung parameter `server_id` pada payload JSON `POST /api/deployments` dan multipart form upload `POST /api/deployments/upload`.
     * File: internal/deployer/store_db.go: Kolom `server_id` diintegrasikan pada queries PostgreSQL (Create, Get, Update, List) dengan penanganan safe NULL/COALESCE.
