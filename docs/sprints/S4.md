## Sprint goal dan demo outcome

### Sprint Goal
Membangun kapabilitas Bring Your Own Server (BYOS) dan Remote Worker Orchestration pada Cuan: memungkinkan pengguna mendaftarkan remote VPS/server pribadi secara aman via SSH, menyimpan kredensial SSH terenkripsi simetris menggunakan AES-256-GCM KeyVault dengan zero-leakage serialization, melakukan live health probe dan fingerprinting spesifikasi perangkat remote (OS distro, CPU cores, RAM size, latency ping), memilih target deployment fleksibel (Local Co-located vs Remote Server) pada Deploy Wizard Studio, orkestrasi bundle transfer via SFTP/SSH ke sandbox terisolasi `~/cuan-apps/<id>/`, streaming remote stdout/stderr log secara real-time, background process health poller, serta staging E2E drill dan release gate dengan 100% data retention Sprint 1–3.

### Demo Outcome
1. Pengguna membuka Studio Dashboard di tab "Servers" (`/studio/servers`) dan mengeklik tombol "Connect Server".
2. Pengguna memasukkan data koneksi: Nama Server, Host/IP, SSH Port (default 22), Username (default `ubuntu`), dan SSH Private Key (atau public key pairing).
3. Pengguna mengeklik "Test Connection": sistem melakukan probe instan via SSH handshake aman (timeout 5s), membaca info sistem remote (`/etc/os-release`, core CPU, RAM total), mengukur latensi round-trip ping, dan menampilkan kartu spesifikasi server dengan badge "Online" hijau.
4. Kredensial SSH disimpan ke database PostgreSQL tabel `servers` dengan private key terenkripsi AES-256-GCM at-rest; serialization API JSON terbukti menyembunyikan private key (`json:"-"`).
5. Pengguna membuka Deploy Wizard ("Deploy New Project") di Studio Dashboard dan memilih target deployment: memilih salah satu remote VPS yang telah terhubung.
6. Cuan Deployer mentransfer bundle aplikasi via SFTP/SSH ke direktori remote terisolasi `~/cuan-apps/<deployment_id>/`, memverifikasi anti-traversal defense, mengalokasikan internal port, dan mengeksekusi runner aplikasi di background host remote.
7. Pengguna mengamati log stdout/stderr proses remote secara live streaming di log viewer Studio Dashboard dan dapat mengendalikan siklus hidup remote application (Start, Stop, Restart) melalui drawer control panel.

## Target pengguna dan nilai produk

### Persona Target Market
1. **Solo Developer & Indie Hackers:** Telah memiliki VPS murah (seperti Hetzner, DigitalOcean Droplet, Linode, Contabo, atau VPS lokal) dan menginginkan kemudahan orkestrasi deploy layaknya PaaS komersial tanpa harus membayar biaya langganan bulanan mahal per server.
2. **Freelance & Digital Agency:** Mengelola banyak proyek klien di beberapa server VPS terpisah dan membutuhkan satu central dashboard Cuan untuk memantau, mendistribusikan, dan mengontrol deploy script klien secara terpusat.
3. **Founding Backers & Self-Hosted Enthusiasts:** Pengguna Cuan mandiri yang ingin memisahkan node web panel/control plane Cuan dari node beban kerja aplikasi (*workload separation*) demi skalabilitas dan isolasi keamanan tinggi.

### Pertimbangan Kepuasan Target Market (DoD Focus)
- **Zero-Friction Server Setup:** Cukup sediakan IP, port, user, dan SSH key; sistem melakukan koneksi, probe, dan fingerprinting otomatis tanpa perlu install agent software tambahan di server target (*agentless SSH orchestration*).
- **Keamanan Kredensial Tingkat Militer:** Private key SSH wajib terenkripsi simetris AES-256-GCM menggunakan master key vault (`VAULT_MASTER_KEY`). Field private key tidak boleh terekspos di respons API publik maupun audit log.
- **Transparansi Performa & Health:** Status server dan resource (OS, CPU, RAM, status ping) terlihat jelas dan terbarui secara berkala.
- **Fleksibilitas Deployment Target:** Bebas memilih apakah aplikasi dijalankan secara co-located di mesin lokal Cuan (LocalDriver) atau di VPS remote (RemoteSSHDriver) hanya dengan 1-klik di modal deploy.

## Fondasi teknis dan arsitektur

- **Backend:** Go (Golang) menggunakan `net/http` dan router `chi/v5`.
- **Database:** PostgreSQL dengan skema aditif migrasi `000009_servers_byos.up.sql`:
  - Tabel baru `servers` (`id`, `name`, `host`, `port`, `username`, `auth_type`, `encrypted_key`, `key_fingerprint`, `status`, `last_ping_at`, `os_info`, `created_at`, `updated_at`).
  - Penambahan kolom foreign key `server_id` pada tabel `deployments` (`REFERENCES servers(id) ON DELETE SET NULL`).
  - Menjamin 100% retensi data Sprint 1 (`owners`, `projects`, `tasks`), Sprint 2 (`sponsors`, `sponsorship_orders`), dan Sprint 3 (`deployments`, `deployment_logs`).
- **Encrypted Key Vault (`internal/crypto/vault.go`):**
  - Enkripsi simetris AES-256-GCM dengan 12-byte random nonce, base64 encoding, dan key derivation dari `VAULT_MASTER_KEY` (dengan fallback deterministik di lingkungan non-produksi).
  - Sanitasi DTO dengan tag `json:"-"` untuk memblokir kebocoran private key ke publik.
  - Perhitungan fingerprint OpenSSH SHA-256 standar (`SHA256:...`).
- **SSH Client & Connector (`internal/deployer/ssh_client.go`):**
  - Menggunakan library resmi `golang.org/x/crypto/ssh` dengan connection timeout 5s dan keepalive.
  - Remote system probe via shell commands (`uname`, `os-release`, `nproc`, `free -m`).
- **RemoteSSHDriver (`internal/deployer/ssh_driver.go`):**
  - Mengimplementasikan interface `DeployDriver` (`Deploy`, `Start`, `Stop`, `Restart`, `GetLogs`, `Delete`).
  - Isolasi sandbox remote di direktori `~/cuan-apps/<deployment_id>/` dengan perlindungan anti-path traversal.
- **Frontend Studio UI:**
  - Komponen React + TypeScript + Tailwind CSS + shadcn/ui di `web/src/components/studio/ServersView.tsx`.
  - Pilihan deployment target di `DeployWizardModal.tsx`.

## Infrastruktur, routing, dan staging gate

1. **Host & Port:**
   - Stable: Port `8080` (reverse proxy Caddy HTTPS).
   - Staging: Port `8081` (Compose project terisolasi, database terpisah).
   - Remote Host: Standard port `22` (dapat dikonfigurasi per server).
2. **Data Retention & Compatibility Gate:**
   - Migrasi `000009_servers_byos.up.sql` murni aditif dan foreign key `deployments.server_id` menggunakan `ON DELETE SET NULL`.
   - Data deployments lokal dari Sprint 3 tetap beroperasi normal dengan `server_id = NULL` (fallback ke `LocalDriver`).
   - Rollback migrasi `000009_servers_byos.down.sql` wajib membersihkan kolom dan tabel `servers` tanpa menghapus data tabel lainnya.

## Out of scope eksplisit

- Multi-cloud auto-provisioning API (membuat VM otomatis via AWS EC2, DigitalOcean Droplet API, Hetzner API, atau Terraform) — pengguna membawa server VPS sendiri yang telah aktif (*Bring Your Own Server*).
- Kompleksitas cluster Kubernetes / Docker Swarm — Sprint 4 berfokus pada eksekusi proses remote via native runtime sandbox.
- Otomasi setup WireGuard / Mesh VPN overlay antar node — komunikasi terenkripsi langsung memanfaatkan protokol secure SSH.
- Billing / invoice / metering biaya pemakaian resource server klien.

## Risiko dan respons

| Risiko | Dampak | Respons / Mitigasi |
| --- | --- | --- |
| Kebocoran SSH private key akibat log atau respons API | Akun VPS pengguna terkompromi | Enkripsi AES-256-GCM at-rest dengan master key, DTO masking `json:"-"`, pembersihan private key dari memori setelah koneksi terjalin |
| SSH connection timeout atau kegagalan jaringan (*network blip*) | Request HTTP hanging atau deployer macet | Strict timeout 5 detik pada koneksi/handshake, non-blocking health probe, auto-reconnect logic berbatas waktu |
| Eksploitasi path traversal pada transfer berkas SFTP remote | Berkas ditransfer ke folder sistem berbahaya di remote VPS | Sanitasi path ketat (`filepath.Clean`), penolakan `..`, pematokan direktori wajib di `~/cuan-apps/<id>/` |
| Regresi migrasi database saat alter `deployments` | Deployment Sprint 3 gagal terbaca atau crash | Kolom `server_id` bersifat nullable dengan `ON DELETE SET NULL`, query existing tetap aman tanpa memutus data lama |
