## Sprint goal dan demo outcome

### Sprint Goal
Mengembangkan Cuan menjadi **"Automated Environment Provisioner & 1-Click Script Deployer"**, melengkapi alur Sprint 11 (di mana script ZIP telah diekstrak dan dideteksi) menjadi platform turnkey end-to-end yang mampu:
1. **Automated Database Provisioning & Schema Importer:** Menyediakan database terisolasi sesuai engine script yang dideteksi (MySQL, PostgreSQL, SQLite) dan otomatis mengimpor berkas skema `.sql` yang ditemukan pada paket ZIP tanpa campur tangan manual via phpMyAdmin/CLI.
2. **Environment Secrets Vault & AES-256-GCM Encryption:** Menghasilkan kredensial acak yang aman (database password, application secret keys) dan menyimpan variabel environment `.env` terenkripsi menggunakan AES-256-GCM dengan zero plaintext leakage.
3. **Runtime Build Runner & Process Supervisor:** Mengeksekusi instalasi dependensi (`composer install`, `npm install`, `pip install`) di sandbox terisolasi, mengalokasikan port dinamis non-bentrok, dan memonitor lifecycle service via health check poller.
4. **Caddy Reverse Proxy & Automatic SSL:** Mendaftarkan port dan domain aplikasi secara dinamis ke konfigurasi reverse proxy Caddy dengan penerbitan sertifikat SSL otomatis.
5. **Interactive 1-Click Deployer Wizard & Live Build Console:** Menyediakan multi-step wizard intuitif di Kanban/Studio dengan streaming logs real-time dan kontrol service in-app ("Open Live App", "Restart", "View Logs").
6. **Strict Data Retention & Dokumentasi Mandiri:** Menjaga keutuhan 100% data Sprint 1–11 dan menyusun panduan operasional mandiri di `docs/guides/script_deployer_provisioner_guide.md` berstandar diagram D2 TALA.

### Demo Outcome
1. Pengguna membuka project hasil ZIP script onboarding (misal: script web Laravel, Node.js, atau Python/Flask).
2. Di Kanban board atau tab Deployer, pengguna menekan tombol **"1-Click Deploy Script"**.
3. Muncul multi-step modal wizard `ScriptDeployerModal`:
   - **Step 1 (Environment & Secrets):** Form visual konfigurasi `.env` dengan tombol *Auto-generate Secrets* (APP_KEY, JWT_SECRET, dsb.).
   - **Step 2 (Database Provisioning):** Pengguna memilih engine database (MySQL/PostgreSQL/SQLite); sistem otomatis membuat database, user, password aman, dan mengimpor file skema `.sql`.
   - **Step 3 (Server & Domain Allocation):** Pemilihan target server (Local Docker sandbox atau BYOS VPS) serta alokasi port dinamis dan domain/subdomain.
   - **Step 4 (Live Build & Launch):** Terminal console menampilkan streaming log real-time saat dependensi runtime dipasang dan service dijalankan.
4. Reverse proxy Caddy secara otomatis merutekan traffic publik ke port aplikasi yang berjalan dengan HTTPS aktif.
5. Pengguna menekan tombol **"Open Live App"** — aplikasi web script yang dibeli langsung terbuka di browser, merespons HTTP 200, dan siap digunakan tanpa satu baris pun perintah terminal manual.

## Target market dan pertimbangan kepuasan DoD (§4)

### Persona Target Market
1. **Pembeli Script Online / Solopreneur Non-Tech:**
   - Membeli script web/aplikasi di CodeCanyon, Envato, atau GitHub marketplace.
   - Kerap frustrasi karena gagal setup database, bingung mengedit `.env`, atau tidak paham cara menjalankan command `composer install` / `npm run build` di VPS.
   - *Kebutuhan:* Alur 1-klik yang mengurus database, dependensi, dan rilis web server secara otomatis.
2. **Digital Agency & Freelancers:**
   - Sering menerima order setup atau kustomisasi web dari klien menggunakan source code siap pakai.
   - *Kebutuhan:* Tool deployment cepat yang bisa mendemokan script klien dalam hitungan menit di domain staging/live.
3. **Indie Hackers & SaaS Builders:**
   - Menguji validasi MVP berbagai produk menggunakan template dan boilerplate script.
   - *Kebutuhan:* Kemudahan provisioning multi-database dan alokasi port terisolasi tanpa merusak service lain di server yang sama.

### Pertimbangan Kepuasan Target Market (DoD Focus)
- **Zero-Friction Script Onboarding to Live URL:** Dari file ZIP hingga web live hanya membutuhkan beberapa klik wizard tanpa perlu SSH terminal.
- **Zero Credential Leakage (AES-256-GCM Vault):** Password database dan secrets env tidak pernah disimpan dalam plaintext dan tidak terekspos di API JSON.
- **Transparent Build Feedback:** Streaming logs transparan memberikan kepastian proses tanpa blank/freezing screen.
- **Strict Data Retention (100% Data Integrity):** Skema database 000017 murni aditif non-destruktif; seluruh data dari Sprint 1–11 tetap 100% utuh tanpa regresi.

## Out of Scope Eksplisit
* Eksekusi kode arbitrary root tanpa isolasi sandbox/container.
* Multi-node Kubernetes clustering / Docker Swarm orchestrator (fokus pada single-node worker VPS & local sandbox).
* Sistem billing/payment gateway untuk biaya sewa server pihak ketiga.

## Risiko & Mitigasi

| Risiko | Dampak | Mitigasi |
| :--- | :--- | :--- |
| **Kebutuhan Ekstensi Bahasa / Versi Berbeda** | Build dependensi gagal | Deteksi kebutuhan versi pada inspector dan validasi runtime sebelum eksekusi build |
| **Sintaks SQL Khusus / Error Impor** | Database tidak terisi sempurna | Pre-validation dialek SQL dan rollback transaction jika gagal |
| **Port Collision pada Target Host** | Konflik service binding | Alokasi port dinamis via `port_pool.go` dengan verifikasi ketersediaan port pre-flight |
| **Kebocoran Kredensial Database / Env** | Risiko keamanan data | Masking field sensitif di seluruh antarmuka dan enkripsi AES-256-GCM |
| **Integritas Database Pasca-Migrasi 000017** | Kerusakan data historis | Skema migrasi murni aditif non-destruktif dengan verifikasi 100% data retention |
