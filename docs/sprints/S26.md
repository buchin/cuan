## Outcome and target market

Solo developers can connect a second Google account without replacing the first, choose the account for each agent, understand actual connection/availability, and recover from Inbox failure without losing or duplicating their message. No room is required. Account A's quota must not prevent starting OAuth for account B. Multiple agents using one account visibly share that account's provider quota; do not claim extra quota or fake remaining balances.

## Implementation findings and dependencies

Current CLI auth session and probe inherit a shared HOME/config and auth-init reuses a global in-flight session. Existing execution paths also inherit the service account. Account isolation must cover login, probe, refresh, Inbox and task PTY; a dropdown alone is insufficient. Existing agent_connections stores encrypted credential metadata and agents already map connection IDs, but current metadata/retry persistence may require additive schema support. Inspect/reuse existing capabilities first; do not invent labels or overload unrelated columns to avoid a justified migration.

Google account-owner consent is an external dependency for a genuine second-account login. Credential entry belongs only in the Cuan dialog, never chat. Provider quota can block live response verification even with valid login. Preserve and report the exact blocked gate; never replace it with synthetic acceptance or repeatedly request login. Non-dependent implementation/tests can continue; unfixable limits go to Review and block any release that cannot meet its acceptance.

## Migration, staging and deployment gates

S25's no-new-migrations constraint remains specific to S25; its 19 migrations must remain byte-for-byte intact. For S26, propose authorization for additive backward-compatible migrations only if existing schema cannot safely represent account metadata or durable request correlation/status. Document necessity and exact schema during implementation before applying to isolated staging. No destructive migration/restore/credential deletion; old code must remain usable for rollback, auto-migrate stays disabled, and a private backup precedes any production schema operation. Do not run down migrations during ordinary application rollback. If compatibility cannot be met, stop release and bring options to Review.

Use existing isolated staging DB/port 8081 and native scripts/fural-deploy.sh plus activate-release.py. Preserve current production until staging gates pass. Production release requires full evidence of isolation, existing @pin1/history continuity, factual status, durable failure/retry behavior, health/readiness, exact static version and rollback. A push alone is not deployment. Staging consent tokens/credentials and production credentials remain private and separate unless a same-owner continuity transfer is explicitly appropriate and documented.

## Risks and limitations

- Antigravity may read additional shared paths/keyring settings: test actual CLI behavior, use isolated child environments/profiles, and never mutate global environment or copy all service secrets into subprocesses.
- Provider identity/remaining quota may not be exposed reliably: show unknown rather than fabricate email, balance or readiness.
- A client timeout can occur after the server persisted/executed the request: durable request correlation and bounded retries must prevent duplicate work.
- Existing OAuth state/profile continuity and mobile composer behavior are regression gates.
- Real multiaccount login requires owner consent; actual provider availability cannot be guaranteed by UI or fixture tests.

## Explicit out of scope

No rooms, group chat, mentions, agent-to-agent delegation, autonomous orchestration, new providers, account auto-rotation/failover, provider-quota bypass, account deletion/revocation, new permissions product, broad model picker, new agent roles/instruction editor, or stop/resume product expansion. Detailed/contextual reply improvements beyond preserving the existing Inbox context are deferred. Scope is the four recommended foundations and their required release/documentation.
