## 1. Sprint Goal dan Demo Outcome

### Sprint Goal
Memungkinkan anggota tim mendaftarkan akun agent mereka sendiri (Antigravity CLI `agy`, Commandcode, dll.) ke Cuan secara mandiri tanpa API key mentah. Saat task dijalankan ("Run Agent" di Papan Tasks / SidePeek), task benar-benar dieksekusi secara otonom di terminal PTY nyata di server dengan streaming interaktif langsung via `xterm.js` di browser web persis seperti Fural.

1. **Agent CLI Account Onboarding & Session Store (S22.1):**
   Mekanisme penyimpanan sesi akun agent per-member (bukan plain API key) di server; command CLI/device pairing otorisasi; deteksi ketersediaan binary agent di host server (`agy`, `claude`, shell).
2. **PTY Task Runner Engine with Agent Dispatcher (S22.2):**
   Integrasikan engine PTY `internal/terminal/pty.go` & `internal/server/terminal_handlers.go` ke eksekusi task otonom. Saat task dijalankan, runner men-spawn binary agent yang terikat di direktori workspace task dengan streaming bidirectional PTY. Endpoint `POST /api/v1/tasks/{id}/run-agent` men-spawn PTY process; WebSocket `/api/v1/tasks/{id}/terminal` streaming stdin/stdout bidirectional secara real-time. Exit code dan history tersimpan.
3. **Interactive Web Terminal (xterm.js) di Task SidePeek (S22.3):**
   Implementasi terminal xterm.js sungguhan menggunakan `@xterm/xterm`, `@xterm/addon-fit`, dan `@xterm/addon-web-links` pada tab Runner di `TaskSidePeek.tsx`. Koneksi WebSocket live, auto-fit resize, rendering ANSI color, dan interaksi keyboard.
4. **Agent Assignment & Status Indicators (S22.4):**
   Di Papan Tasks dan Task SidePeek, user dapat memilih akun agent mana yang ditugaskan menjalankan task. Indikator visual status agen (Idle, Running dot hijau, Completed, Error) tampil sinkron.
5. **Staging Drill, VPS cuan.dojo.cc Deployment & Operational Guide (S22.5):**
   Verifikasi WebSocket di balik reverse proxy VPS `cuan.dojo.cc`, zero database regression, dokumen SSOT `docs/sprints/S22.md`, dan panduan operasional di `docs/guides/agent_runner_terminal_guide.md` dengan diagram D2 TALA. Live di `https://cuan.dojo.cc`, Web Terminal xterm.js terhubung mulus via WSS, targeted tests PASS, commit pushed ke `origin/main`.

## 2. Target Market dan Pertimbangan Kepuasan DoD (§4)

### Target Market
* **Solopreneur & Pengembang Mandiri (Dojo Creators & Solo Devs):** Menggunakan Cuan sebagai pusat kendali otonom untuk mendelegasikan tugas teknis langsung ke agen CLI (`agy`, `claude`, shell script) tanpa harus mengetik perintah manual di server SSH.
* **Tim Kolaboratif Multi-Member:** Setiap anggota tim dapat memasangkan agen mereka masing-masing dengan kuota akun sendiri tanpa berbagi API key berisiko kebocoran.
* **Operator On-The-Go:** Memantau kemajuan kerja agen secara visual melalui terminal browser interaktif di laptop maupun smartphone.

### Mengapa Target Market Bakal Senang dengan DoD Ini?
* **Zero Plain API Keys:** Tidak perlu lagi menyalin dan menempel token API sensitif ke antarmuka web; cukup pairing device session layaknya menghubungkan perangkat CLI modern.
* **Real-Time Interactive Transparency:** Tidak lagi menunggu "kotak hitam" selesai tanpa kejelasan; user dapat melihat ANSI terminal streaming langsung baris demi baris, bahkan mengambil alih kontrol keyboard jika agen meminta konfirmasi.
* **Clear Task Assignment:** Di papan Kanban terlihat jelas siapa yang sedang mengerjakan task (Scrum Master, Antigravity Flash Worker, atau Architect) dan apakah agen sedang aktif bekerja (indikator dot hijau menyala).

## 5. Detail Backlog Tasks (S22.1 – S22.5)

### S22.1 — Agent CLI Account Onboarding & Session Store
- **Scope:**
  - `internal/agent/session_store.go`:
    * Struktur data `AgentSession`: `ID`, `MemberID`, `AgentID`, `AgentName`, `Provider`, `BinaryType`, `BinaryPath`, `Token`, `DeviceCode`, `Status`, `CreatedAt`, `ExpiresAt`.
    * Deteksi ketersediaan binary agent di host server (`DetectAgentBinaries()`): mengecek `agy`, `claude`, `bash`, `sh`, path eksekutabel, dan versinya.
    * Penyimpanan sesi akun agent per-member (bukan plain API key) dengan otorisasi berbasis device pairing.
    * Validasi sesi dan mekanisme revocasi/rotasi token.
  - `cmd/server/main.go`:
    * Dukungan CLI flag untuk otorisasi pairing agent: `--pair-agent`, `--code`, `--agent-id`, `--member-id`.
    * Flag `--detect-agents` untuk menampilkan deteksi binary host secara instan.
  - `internal/server/`:
    * Endpoint `GET /api/v1/agents/binaries`: daftar binary yang terdeteksi di server.
    * Endpoint `POST /api/v1/agents/pair`: inisiasi/konfirmasi pairing kode otorisasi agen.
    * Endpoint `GET /api/v1/agents/sessions`: daftar sesi agen yang aktif per member.
    * Endpoint `DELETE /api/v1/agents/sessions/{id}`: cabut sesi agen.
- **DoD:**
  1. Anggota tim dapat mengotorisasi akun agent mereka tanpa mengekspos API key mentah.
  2. Server mendeteksi binary agent di host server (`agy`, `claude`, `bash`, `sh`).
  3. Sesi tervalidasi di backend dengan token aman.
  4. Unit test session storage PASS 100%.

### S22.2 — PTY Task Runner Engine with Agent Dispatcher
- **Scope:**
  - `internal/terminal/manager.go`:
    * Implementasikan `RunTaskAgent(ctx, cfg)`:
      - Validasi Task ID dan isolasi workspace task (`data/workspaces/{task_id}`).
      - Tentukan binary yang dijalankan (`agy`, `claude`, atau interactive shell runner).
      - Spawn proses PTY nyata menggunakan `SpawnPTY`.
      - Kaitkan proses dengan session manager untuk streaming ke WebSocket.
      - Rekam exit code, output buffer, dan perbarui `execution_status` di task store saat proses selesai.
  - `internal/server/terminal_handlers.go`:
    * Endpoint `POST /api/v1/tasks/{id}/run-agent` (dan alias `/api/tasks/{id}/run-agent`):
      - Menerima payload opsional `agent_id`, `prompt`, `binary`, `cols`, `rows`.
      - Memanggil runner dispatcher.
      - Mengembalikan status `running`, `session_id`, `task_id`, `pid`.
    * Endpoint `GET /api/v1/tasks/{id}/run-agent/history`:
      - Mengembalikan riwayat eksekusi, exit code, dan durasi.
  - `internal/server/server.go`:
    * Daftarkan route `POST /api/v1/tasks/{id}/run-agent` dan route terkait.
- **DoD:**
  1. Endpoint `POST /api/v1/tasks/{id}/run-agent` men-spawn PTY process di server.
  2. WebSocket `/api/v1/tasks/{id}/terminal` streaming bidirectional PTY stdin/stdout secara real-time.
  3. Exit code dan history tersimpan di backend.
  4. Unit test runner engine PASS 100%.

## 8. Risiko & Mitigasi

| Risiko | Dampak | Mitigasi |
| :--- | :--- | :--- |
| **Binary Agent Belum Terpasang di Host** | Eksekusi task gagal jika memanggil binary non-existent | Deteksi ketersediaan binary host (`DetectAgentBinaries()`); fallback cerdas ke interactive shell runner dengan banner informatif |
| **WebSocket Terputus di Balik Reverse Proxy** | Streaming terminal terputus di tengah jalan | Nginx VPS telah dikonfigurasi dengan `proxy_read_timeout 86400s`, `Upgrade $http_upgrade`, dan ping/pong heartbeat interval 15s |
| **Zombie Process pada PTY Terbengkalai** | Beban memori VPS meningkat | Background idle sweeper membersihkan sesi tanpa subscriber setelah batas timeout |
| **Regresi Database** | Data task atau chat terganggu | Penguncian skema pada 19 migrasi stabil yang sudah ada dan pengujian zero regression di staging |
