# Cuan Sprint 31 — Scrum Master Mobile-Safe Layouts, Code Peeking & Pre-Flight Feasibility Matrix

## Rekomendasi untuk PO (diajukan SM)

**Rekomendasi:** Approve scope S31 di bawah ini — meningkatkan kapabilitas Scrum Master (`@sm`) dari sekadar "cukup" menjadi "world-class AI Tech Lead" untuk pengguna non-developer dan komunitas Open Source internasional. Peningkatan meliputi:
1. **Mobile-Safe Visual Wireframing:** Format tata letak visual berbasis *compact hierarchy* (< 36 karakter) dan diagram terstruktur yang tidak pecah saat dilihat di layar smartphone (viewport 360px–390px).
2. **Targeted In-Chat Code Peeking:** Pemanfaatan 1–2 kuota read-only tools secara proaktif untuk membaca baris JSX/kode riil komponen target dan mengutip baris kodenya secara faktual (bukan sekadar menyebutkan nama file).
3. **Pre-flight Feasibility & Technical Impact Matrix:** Matriks ringkas 3–4 baris ramah non-developer (kompleksitas, dampak database/migrasi, kesiapan API backend, dan resiko *blast radius*) pada setiap konsultasi fitur baru.

**Alternatif:** Membiarkan SM seperti di S30 — fungsionalitas dasar sudah berjalan baik, tetapi wireframe ASCII lebar berisiko berantakan di HP dan SM belum proaktif mengutip baris kode faktual.

**Alasan:** PO memberikan otorisasi eksplisit ("Gas.") untuk merealisasikan standar Tech Lead yang mendampingi non-developer secara profesional, akurat, dan mobile-ready.

## Tujuan Sprint

1. **Mobile-Safe Wireframe Standard (`coordinator.md` & `inbox_coordinator_response.go`):**
   - Menghilangkan format ASCII art tabel lebar (> 40 karakter) yang rentan patah (*line-wrapped*) di viewport smartphone 360px–390px.
   - Menggantinya dengan representasi *compact nested hierarchy* (< 36 karakter per baris) atau diagram Mermaid yang otomatis responsif.
2. **Targeted Code Peeking Directive (`coordinator.md` & `inbox_coordinator_response.go`):**
   - Mengarahkan SM untuk menggunakan 1–2 dari 12 alokasi *read-only tool calls* (`read_file`, `view_code_item`) guna membaca baris komponen persis dan mengutip nomor baris serta hierarki JSX riil.
3. **Pre-flight Feasibility & Technical Impact Matrix:**
   - Menstandarisasikan format ringkasan teknis 3–4 baris yang ramah non-developer:
     - *Kompleksitas Scope* (Focused Single-Task vs Multi-tier Epic)
     - *Dampak Database* (Nol migrasi vs Butuh migrasi skema)
     - *Kesiapan API Backend* (Endpoint sudah ada vs Butuh endpoint baru)
     - *Risiko Regresi / Blast Radius* (Aman terisolasi di UI vs Komponen global)
4. **Verifikasi & Deploy Produksi:**
   - Targeted unit test di `internal/server/` dan `web/` lulus 100%.
   - Deployment live ke `https://cuan.dojo.cc` dan verifikasi `/healthz`.
