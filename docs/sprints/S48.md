## Outcome Sprint & Kesepakatan PO

**Outcome:** Menghadirkan kapabilitas **Dynamic Model Discovery, Provider Catalog Probing, dan Resilient Agent Fallback** pada platform Cuan. Menggantikan daftar model AI statis (*hardcoded*) dengan penemuan katalog model dinamis langsung dari *provider harness* (AGY, Google Gemini, CommandCode, dsb.) yang dilengkapi *caching thread-safe* ber-TTL 5–10 menit, aksi penyegaran instan (*Refresh Catalog*), penanda visual kapabilitas model (*Vision vs Text-only*), dukungan input model kustom (*Custom Model ID*), serta pemilihan model cadangan (*fallback model*) yang cerdas. Fitur ini menjamin agen bisnis milik UMKM dan solopreneur selalu adaptif terhadap perkembangan model AI terbaru, tidak pernah mogok saat terjadi *quota exhaustion* atau pembaruan model, dan memberikan kendali fleksibel tanpa friksi teknis.

**Kesepakatan & Arahan PO (diajukan SM, disetujui PO):**
1. **Dynamic Model Discovery & Provider Registry Probing (Backend)**:
   - Mengintegrasikan mekanisme probing model dinamis pada `internal/agent/` dan `internal/server/agent_handlers.go`.
   - Mengoptimalkan native CLI / API probing untuk provider dengan *thread-safe in-memory caching* bertempo waktu (TTL 5–10 menit) untuk mengeliminasi latensi eksekusi berulang.
   - Menyediakan dukungan *forced refresh* via parameter `?refresh=true` pada endpoint API untuk memperbarui katalog secara instan.
   - Memperbarui kontrak respon `GET /api/v1/agents/{id}/model-config` dan `GET /api/v1/agents/models` agar menyertakan atribut metadata lengkap: `id`, `name`, `provider`, `capabilities` (misal flag `vision: true/false`), dan deskripsi ringkas.
2. **Frontend Dynamic Model Selector, Badging & Refresh Action**:
   - Merombak `web/src/features/team/EditAgentModal.tsx` dan `web/src/features/team/TeamView.tsx`: menyingkirkan opsi model hardcoded.
   - Menghadirkan komponen pemilih model (*Dynamic Model Picker*) dengan badge visual yang jelas (*Vision* vs *Teks*) sehingga pengguna non-developer langsung memahami kapabilitas masing-masing model.
   - Menambahkan tombol aksi *Refresh Catalog* (Segarkan Model) yang memungkinkan pengguna memperbarui daftar model langsung dari antarmuka saat provider merilis model baru.
   - Menyediakan opsi input *Custom Model ID* untuk fleksibilitas tingkat lanjut tanpa membatasi pengguna pada daftar baku.
3. **Resilient Agent Fallback Architecture**:
   - Memastikan konfigurasi `fallback_model_id` dapat dipilih dan disimpan dengan mudah pada form konfigurasi agen.
   - Apabila model utama mengalami *rate limit*, kehabisan kuota, atau *deprecation*, eksekusi runtime agen secara elegan beralih ke model fallback tanpa menghentikan percakapan pelanggan.
4. **100% Backward Compatibility**:
   - Agen yang telah dikonfigurasi dengan model eksisting tetap berfungsi tanpa gangguan atau reset data.
   - Jika model tersimpan belum/tidak ada di katalog aktif, sistem tetap menampilkannya secara aman (*preserved model identifier*).
5. **Lokalisasi Bahasa Indonesia Menyeluruh**:
   - Seluruh label baru (Segarkan Model, ID Model Kustom, Kapabilitas Vision, Model Cadangan, status pemuatan) diterjemahkan dengan bahasa yang ramah UMKM pada `web/src/locales/id.json`.

## Target Market Fit & Value Proposition

- **Target Market**: Pemilik UMKM, pedagang toko online/e-commerce, solopreneur, dan staf operasional non-developer yang mengandalkan agen AI Cuan untuk melayani obrolan pelanggan (WhatsApp/Telegram/Web), memproses bukti transfer pembayaran (kuitansi/struk belanja), dan menghasilkan materi promosi bisnis.
- **Mengapa Target Market Menyukai Hasil Sprint Ini?**:
  1. **Akses Model AI Terbaru Tanpa Menunggu Update Aplikasi (*Zero-Friction Updates*)**:
     Sebelumnya, saat penyedia AI seperti Google merilis model baru yang lebih cepat atau lebih hemat, pengguna harus menunggu tim pengembang memperbarui kode aplikasi. Dengan Dynamic Discovery, model baru langsung muncul di dropdown atau cukup menekan tombol "Segarkan Model".
  2. **Kejelasan Kapabilitas Bisnis (Anti-Salah Pilih Model)**:
     Banyak pengusaha UMKM mengeluh agen CS mereka tidak bisa membaca foto struk transfer pelanggan karena salah memilih model yang tidak mendukung gambar (*non-vision*). Dengan badge visual "Vision" yang tegas, kesalahan operasional ini dapat dicegah sejak awal.
  3. **Kelangsungan Bisnis Tanpa Henti (*Resilient Business Continuity*)**:
     Bagi toko online yang aktif 24 jam, downtime akibat model utama kehabisan kuota atau mengalami gangguan server AI berarti kehilangan calon pembeli dan omzet. Keberadaan model cadangan (*fallback model*) memastikan toko tetap melayani pelanggan secara kontinu tanpa jeda.
  4. **Kebebasan Eksperimen dengan Custom Model**:
     Bagi pengguna yang ingin memanfaatkan model khusus, model preview, atau model hasil fine-tuning, kolom *Custom Model ID* memberikan fleksibilitas penuh tanpa perlu meminta perubahan kode ke tim teknis.

## Risks & Mitigations

1. **Risk: Latensi Probing Eksekusi CLI Provider**
   - *Dampak:* Jika eksekusi probing CLI (`agy` atau command provider) lambat atau tertahan, respon endpoint `/models` melambat sehingga memperlambat pembukaan modal di UI.
   - *Mitigasi:* Terapkan *thread-safe in-memory caching* dengan TTL 5–10 menit. Bungkus eksekusi CLI dengan `context.WithTimeout` ketat (maksimal 3–5 detik). Jika probing CLI timeout atau gagal, gunakan *stale cache* atau fallback katalog default tanpa memblokir request pengguna.
2. **Risk: Provider Rate Limit atau Gangguan Jaringan Saat Refresh On-Demand**
   - *Dampak:* Pengguna menekan tombol "Segarkan Model" saat koneksi ke provider sedang terganggu, menyebabkan error 500.
   - *Mitigasi:* Terapkan *graceful degradation*. Jika request probing gagal saat refresh, sistem mengembalikan daftar model terakhir yang valid disertai notifikasi halus (toast alert) bahwa penyegaran gagal dan model saat ini tetap dapat digunakan.
3. **Risk: Kesalahan Ketik pada Opsi Custom Model ID**
   - *Dampak:* Pengguna memasukkan ID model kustom yang tidak valid atau salah ketik sehingga agen gagal saat pertama kali merespons percakapan.
   - *Mitigasi:* Lakukan sanitasi format string (karakter alfanumerik, garis bawah, titik, dan strip). Sediakan konfigurasi model fallback wajib sehingga jika model kustom gagal dieksekusi oleh harness saat runtime, agen otomatis beralih ke model cadangan.
4. **Risk: Regresi Konfigurasi Agen Eksisting di Database**
   - *Dampak:* Agen yang sudah dibuat di masa lalu dengan ID model lama tiba-tiba kehilangan konfigurasi atau reset ke default saat modal dibuka.
   - *Mitigasi:* Pertahankan *backward compatibility* secara mutlak. Nilai `model_id` dan `fallback_model_id` yang tersimpan di database selalu dipreservasi. Jika model tersimpan tidak ada di katalog hasil probe, sistem tetap menyajikannya sebagai opsi terpilih (dengan penanda *unlisted / legacy*) tanpa mengubah konfigurasi agen secara diam-diam.
