## Sprint goal dan demo outcome

Owner memasang Cuan di VPS, menghubungkan repo Cuan, membuat task pengembangan, menjalankan satu coding agent, memeriksa perubahan dan bukti verifikasi, serta mendapatkan PR di GitHub. Perubahan kemudian diuji di staging dan dipasang ke instance Stable tanpa kehilangan task atau riwayat kerja.

## Infrastruktur: apakah perlu VPS baru?

**Tidak wajib.** VPS existing boleh dipakai setelah inventory kapasitas, OS, disk, port, layanan aktif, dan kredensial akses. Tidak mencetak secrets dalam laporan.

**Rekomendasi:** VPS khusus dogfooding agar eksperimen tidak mengganggu produk existing. Kandidat minimum uji 2 vCPU/2 GB RAM; 4 GB lebih lega jika database, frontend build, agent, dan staging berada di host yang sama. Kapasitas belum dibenchmark; upgrade bukan jaminan semua workload muat.

**Alternatif:** VPS existing yang lulus preflight — biaya tambahan lebih kecil, tetapi perlu batas resource dan pemisahan layanan yang lebih hati-hati.

Gate sebelum staging/deploy:

1. Tetapkan host, kapasitas, direktori data, anggaran disk, domain/subdomain, dan lokasi backup.
2. DNS mengarah ke host; port 80/443 tersedia. Jika reverse proxy sudah ada, gunakan integrasi existing tanpa menimpa konfigurasinya.
3. Stable dan staging punya Compose project, database, storage, network, dan hostname terpisah. Agent tidak mengedit file instalasi Stable.
4. Runner menjalankan workspace task dengan batas CPU/RAM, non-root bila kompatibel, dan hanya akses repo/secrets yang diperlukan. Proses agent tidak diberi Docker socket atau kredensial infrastruktur global.
5. Agent/model dan GitHub credentials milik user tersedia melalui konfigurasi aman, bukan source control atau log.
6. Provisioning berbayar atau upgrade VPS dilakukan setelah pilihan host/biaya disepakati. Sprint approval tidak otomatis mengotorisasi pembelian yang belum ditentukan.

Snapshot harga publik Helipod yang dilihat pada 2026-10-16: EU 2 vCPU/2 GB/30 GB SSD Rp46.665/bulan; EU 4 vCPU/4 GB/60 GB SSD Rp101.915/bulan. Ini harga tampilan halaman promo, bukan jaminan renewal/pajak/stock. Sumber: https://helipod.io/vps-murah.

## Backlog berurutan, dependency, dan DoD

ID di bawah adalah ID planning, belum ID task board. Satu branch aktif untuk implementasi besar; perubahan agent dogfooding memakai branch task tersendiri setelah branch implementasi siap digabung. Pertahankan branch unmerged/PR aktif; hapus branch merged setelah verifikasi.

### T1 — Tetapkan fondasi dan kelayakan agent

- Dependency: scope sprint approved; repo Cuan tersedia.
- Scope: struktur monorepo aplikasi/runner/UI; konfigurasi development; keputusan lisensi; spike adapter satu agent; catat keputusan arsitektur dan threat boundaries.
- DoD: build minimum berhasil; migration baseline dapat dijalankan; agent terpilih mampu menerima instruksi headless, mengedit fixture repo, melaporkan selesai, dan dihentikan. Auth server serta konsumsi resource diukur tanpa membuka secrets. README menjelaskan status pre-release dan cara development.
- Bukti: commit, perintah dan exit status, hasil spike, versi agent, serta catatan keputusan.

### T2 — Sediakan instalasi persisten dan akses owner

- Dependency: T1.
- Scope: API/UI shell, PostgreSQL, login owner tunggal, setup pertama terlindungi, Compose, health/readiness, persistent volumes, konfigurasi proxy HTTPS.
- DoD: pemasangan lewat README pada lingkungan bersih; hanya owner terautentikasi yang mengakses project/task; setup tidak bisa diambil alih pengunjung publik; restart mempertahankan data; secrets tidak di-commit. Database tidak diekspos publik secara default.
- Bukti: smoke install/login/restart, health response, contoh konfigurasi tanpa secrets, panduan port/domain dan mode existing proxy.

### T3 — Hubungkan repository GitHub existing

- Dependency: T2.
- Scope: project dari repo existing, default branch, akses GitHub milik owner, clone/fetch; halaman Projects dan project detail. Gunakan satu metode autentikasi GitHub terdokumentasi; tidak wajib GitHub App pada sprint ini.
- DoD: repo Cuan dapat dihubungkan; repo tidak ditemukan/akses ditolak ditampilkan informatif; kredensial tersimpan aman dan tidak masuk log; penghapusan project tidak menghapus remote repo. Repo adalah source of truth kode.
- Bukti: koneksi repo nyata, kasus akses ditolak, serta panduan konfigurasi/revoke credential.

### T4 — Bangun task board dan histori pekerjaan

- Dependency: T3.
- Scope: task title/instructions, project, assignment agent, status, komentar, activity, UI Tasks. Pisahkan status task dari status attempt eksekusi.
- DoD: owner membuat/mengubah task dan membuka detail; restart tidak menghilangkan data; histori mencatat transisi; kegagalan tidak ditampilkan sebagai sukses. Status minimal backlog/doing/review/done dengan attempt queued/running/succeeded/failed/canceled/interrupted. Agent tidak otomatis menganggap hasil accepted hanya karena exit code nol.
- Bukti: targeted test transisi/persistence dan walkthrough UI.

### T5 — Jalankan task melalui runner dan satu agent

- Dependency: T1, T4.
- Scope: runner terautentikasi dengan koneksi keluar, queue persisten, heartbeat/lease, log streaming, cancel/timeout, profil agent, CPU/RAM/disk monitoring. UI Agents dan Servers minimal.
- DoD: satu task nyata dieksekusi; task berikutnya antre; cancel menghentikan process tree task; disconnect/restart dilaporkan sebagai interrupted/recoverable tanpa diam-diam menjalankan ulang pekerjaan yang mungkin sudah melakukan side effect. Tidak ada dua runner mengeksekusi attempt sama. Retry eksplisit menjadi attempt baru. Log dibatasi/dirotasi dan credentials disamarkan.
- Bukti: eksekusi, antrean, cancel, restart/disconnect, duplicate-claim test, metrik puncak RAM, dan panduan recovery. Verifikasi panjang dilakukan di AgentSession, bukan chat diskusi.

### T6 — Hasilkan perubahan Git dan PR yang dapat direview

- Dependency: T3, T5.
- Scope: workspace/checkout per task, branch task, perubahan file, targeted validation, commit/push, PR, ringkasan bukti; cegah agent mengubah instalasi Stable atau workspace task lain.
- DoD: task nyata menghasilkan commit dan PR di repo Cuan dengan diff, instruksi verifikasi, hasil test beserta exit status, serta keterbatasan. Branch default tidak dipush langsung oleh agent. Human author identity yang terkonfigurasi dihormati. Owner dapat memeriksa hasil dan meminta revisi pada task yang sama.
- Bukti: PR nyata, commit SHA, log targeted test, satu siklus revisi. Task yang dikembalikan ke doing benar-benar memulai/resume attempt agent dan melaporkan checkpoint.

### T7 — Buktikan staging, update, backup, dan pemulihan

- Dependency: T2, T6; gate infrastruktur terpenuhi.
- Scope: prosedur deploy berbasis versi/image tetap, staging terpisah, backup/restore, health check, rollback, CLI recovery; installer shell sederhana sebagai wrapper Compose jika jalur manual sudah terbukti.
- DoD: fresh install mengikuti docs; hostname HTTPS nyata valid; staging menjalankan hasil build yang dituju tanpa mengganggu Stable; update mempertahankan task/config; backup dapat direstore. Uji satu kegagalan update dan pemulihannya. Migration backward-compatible atau mitigasi pemulihan tertulis dan diuji; rollback image saja tidak dianggap rollback database.
- Bukti: URL deployment, versi/image/commit, smoke test, backup/restore dan rollback drill tanpa data rahasia. Installer melakukan preflight, tidak menimpa instalasi/proxy existing, dan menampilkan error yang bisa ditindaklanjuti.

### T8 — Demo dogfooding dan siapkan release OSS

- Dependency: T1–T7.
- Scope: satu perbaikan nyata Cuan dikerjakan melalui Cuan, onboarding docs, troubleshooting, license/dependency review, release candidate dan Sprint Review pack.
- DoD: owner membuat task di Cuan Stable → agent mengubah repo Cuan → targeted test → PR → review/revisi → merge → staging → update Stable. Task/history tetap ada dan akses CLI recovery tersedia. Penilaian usability oleh agent memakai panduan dari awal; PO berpartisipasi pada Sprint Review, bukan sebagai tester implementasi.
- Release gate: tidak ada secrets/proprietary material yang tidak berhak dipublikasikan; LICENSE/NOTICE sesuai keputusan; dependency license diperiksa; known limitations dan prosedur update/recovery tersedia. Tag/public visibility diputuskan pada review, bukan otomatis dari keberhasilan demo.
- Bukti: task/attempt ID, commit/PR, URL Stable/staging, versi sebelum/sesudah, hasil test, demo screenshot seperlunya, serta catatan gap. Status sprint menjadi review; completed hanya setelah review bersama PO.

## Definition of Done bersama

- Setiap task dilaporkan dengan progres, file/area berubah, verifikasi nyata, commit, deployment bila relevan, dan blocker.
- Targeted automated tests untuk queue/claim, auth, persistence, cancel, Git isolation, dan recovery sesuai perubahan. Tidak menjalankan full suite tanpa alasan esensial.
- Build/typecheck yang relevan lulus; errors informatif; panduan penggunaan/config tersedia. Penilaian keamanan dan usability dilakukan agent yang sesuai.
- Bukti disimpan di `docs/sprints/evidence/S1/` atau tautan CI/PR yang stabil; tidak berisi credentials atau data pribadi.
- SM menilai bukti terhadap DoD. Lulus → jalankan task dependency berikutnya. Agent-fixable → beri gap, area target, verifikasi, dan kriteria selesai lalu lanjutkan sesi. Unfixable → catat blocker/dampak/bukti/opsi untuk review.
- Stable tidak bergantung pada UI Cuan untuk pemulihan; kode berada di GitHub dan data memiliki backup yang telah diuji.

## Risiko dan respons

| Risiko | Dampak | Respons/gate |
| --- | --- | --- |
| Adapter tidak mendukung auth/headless/cancel yang dibutuhkan | Task execution terhambat | Spike T1; pilih adapter yang memenuhi kontrak sebelum T5 |
| RAM/disk penuh saat build atau log bertambah | Agent atau Stable terganggu | Batas resource, antrean, rotasi log, ukur peak; pisahkan host atau upgrade setelah keputusan biaya |
| Runner putus setelah side effect | Duplicate commit/push/pekerjaan | Attempt persisten, claim/lease, interrupted state, rekonsiliasi dan retry eksplisit |
| Bug update mematikan tempat kerja | Tidak bisa memperbaiki lewat Cuan | Stable/staging terpisah, backup diuji, CLI/GitHub recovery |
| Scope terlalu luas untuk satu siklus | Dogfooding terlambat | Satu owner/repo/agent/concurrency; prioritas jalur end-to-end; potong scope hanya lewat PO saat planning atau stop dan re-plan |
| Secret bocor atau akses agent terlalu luas | Kehilangan kepercayaan/data | Akses minimum, redaksi, tanpa Docker socket pada agent, pemeriksaan sebelum publikasi |
