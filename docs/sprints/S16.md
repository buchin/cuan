## Sprint goal dan demo outcome

### Sprint Goal
Me-wipe dan membangun ulang antarmuka pengguna (`web/src`) dari nol menggunakan arsitektur modern, modular, dan snappy (*React + TypeScript + Vite + shadcn/ui*). Menghapus 100% *god-components* lama dan menggantinya dengan pengalaman **Linear-class** yang terfokus murni pada:
1. **Projects Directory & Breadcrumb Switcher:** Navigasi proyek yang cepat dan intuitif tanpa istilah "workspace" yang membingungkan.
2. **Agentic Task Board (Kanban/List):** Pengelolaan task yang terhubung langsung dengan AI Agent.
3. **Side-Peek Execution Panel:** Melihat detail task dan live log eksekusi agent tanpa modal bertumpuk.
4. **Unified Settings:** Seluruh konfigurasi teknis (Server, Domain, Secrets, Repo URL) dipindahkan ke Settings proyek.
5. **Backend & Data Retention:** 100% backend Go dan data database PostgreSQL (19 migrasi) tetap utuh.

### Demo Outcome
1. **Login & Auth Guard:** Pengguna masuk via halaman login Tokyo Night yang bersih (`/login`).
2. **Projects Workspace:** Pengguna melihat daftar proyek dalam format Grid/List minimalis, dapat membuat proyek baru dalam hitungan detik via modal ringkas.
3. **Project Task Board:** Memilih proyek langsung membuka Task Board (Backlog, Todo, In Progress, Done) ala Linear.
4. **Side-Peek Runner:** Mengklik kartu task membuka panel laci dari samping (*side-peek drawer*) yang menampilkan deskripsi tugas, checklist DoD, dan tab live agent terminal saat agent dijalankan.
5. **Zero Nav Clutter:** Sidebar hanya memiliki navigasi esensial (*Projects*, *Tasks*, *Agents*, *Settings*). Tidak ada tombol marketing atau tab server/domain liar di layar utama.

## Target market dan pertimbangan kepuasan DoD (§4)

### Target Market
* **Creator & Digital Solopreneur:** Membutuhkan alat kerja yang hening (*zero clutter*), cepat (*snappy*), dan langsung mengeksekusi tugas konten/aplikasi tanpa kebingungan teknis.
* **Agency / Technical Lead:** Mengelola beberapa proyek sekaligus, butuh kemudahan berpindah proyek dan memantau status tugas agent.

### Mengapa Target Market Bakal Senang dengan DoD Ini?
* **Zero Cognitive Overload:** Tidak ada lagi kebingungan antara "apakah ini cPanel atau task manager?". Mental model menjadi jelas: *Projects → Tasks → Run Agent*.
* **Kecepatan & Responsivitas:** Mengganti monolit 107 KB dengan modul-modul kecil (< 200 baris) membuat UI sangat ringan, instan, dan bebas lag.
* **Keamanan Data:** Proyek dan task yang sudah dibuat sebelumnya di database tidak ada yang hilang (100% backward compatible).

## Out of Scope Eksplisit
* Mengubah skema database backend atau endpoint REST API Go yang sudah stabil (backend tetap dipertahankan 100%).
* Menambah sistem billing atau payment gateway baru pada sprint ini.
* Menghadirkan kembali fitur-fitur marketing/sponsorship/teleprompter lama ke dalam navigasi utama.

## Risiko & Mitigasi

| Risiko | Dampak | Mitigasi |
| :--- | :--- | :--- |
| **API Contract Mismatch** | Frontend baru salah membaca format response JSON lama | Tipe data di `web/src/api/types.ts` disinkronkan secara ketat dengan model DTO Go backend sebelum komponen dibuat |
| **Kehilangan Fungsionalitas Lama** | Fitur penting terlewat saat clean rebuild | Seluruh endpoint esensial (auth, project, task, runner, server, domain) dipetakan ke dalam fitur Projects, Tasks, dan Settings |
| **Downtime Staging/Production** | Pengguna terganggu saat migrasi bundle frontend | Build frontend diuji terlebih dahulu di staging port 8081; deployment ke `cuan.dojo.cc` hanya dilakukan setelah drill lulus 100% |

## Gate Staging & Deployment
* **Staging Gate (Port 8081):** Build frontend baru wajib lulus uji browser / curl pada seluruh rute (`/`, `/login`, `/projects`, `/tasks`).
* **Deployment Gate:** Zero-regression verifikasi API backend Go dan 0 lint/TypeScript error sebelum rilis ke production `cuan.dojo.cc`.
