## Ringkasan Eksekutif & Sasaran Sprint 66

Sprint 66 menjawab tuntas dua komplain utama dari operasional dan pengguna:
1. **Real Native PTY Live Terminal (Bukan Terminal Bohongan):**
   - Terminal saat ini hanya menampilkan teks baris per baris hasil formatting NDJSON (`✔ Run Command ...`, `● Run Command ...`), bukan sesi terminal interaktif yang sesungguhnya.
   - Di Fural, terminal menampilkan TUI asli dari `agy` CLI secara interaktif (live token counter, thinking status, tool call fold/expand via `ctrl+o`, interactive prompt).
   - **Tantangan Arsitektur:** Terminal asli membutuhkan pseudo-terminal (PTY) OS. Sebelumnya, PTY dijalankan langsung di dalam proses web server `cuan`, sehingga ketika web server di-deploy atau di-restart, agen yang sedang bekerja langsung mati terbunuh (*killed*).
   - **Solusi Sprint 66:** Pindahkan engine PTY (`creack/pty`) ke dalam daemon pekerja `cuan-runner`. `cuan-runner` menjalankan `agy` dengan `--prompt-interactive` di dalam PTY slave, lalu mengekspos Unix Domain Socket lokal (`/tmp/cuan-runner-pty-{taskId}.sock`). Web server `cuan-server` bertindak sebagai reverse-proxy WebSocket ke socket tersebut. Jika web server di-deploy/restart, proses agen di `cuan-runner` **tetap hidup 100% aman**, dan browser langsung menyambung kembali (*auto-reconnect*) begitu server aktif.
2. **Pembersihan Total Spam Robot di Chat Room Pelanggan:**
   - Pada ujicoba produksi sebelumnya di room pengunjung (`e66f9df0-e12c-44dd-9dc2-89d87a96a019`), sistem membanjiri ruang obrolan dengan 12 pesan internal robot (*"Work started..."*, *"Execution exceeded hard timeout..."*).
   - Sprint 66 memastikan seluruh status intermediate retry dan error internal diisolasi ketat ke diagnostic runner/slidedrawer dan **dilarang keras** dipancarkan ke ruang obrolan pelanggan.

## Backlog Task Sprint 66

### S66-T1: Decoupled PTY Engine di cuan-runner & Unix Domain Socket Bridge
- **Branch:** `feature/s66-t1-runner-pty-engine`
- **Scope:**
  1. Modifikasi `internal/runner` untuk mengintegrasikan alokasi PTY via `creack/pty` saat menjalankan task agen.
  2. Jalankan `agy` dengan mode `--prompt-interactive` dan `--dangerously-skip-permissions` di dalam PTY slave runner.
  3. Buka Unix Domain Socket lokal untuk setiap sesi aktif (`/tmp/cuan-pty-{taskId}.sock` atau path terkonfigurasi) yang mendukung stream I/O dua arah (input keyboard, output raw terminal, dan resize command).
  4. Tetap catat transcript dan raw logs untuk persistensi riwayat tugas.
- **DoD:**
  - `cuan-runner` berhasil mengeksekusi proses agen di dalam PTY asli.
  - Socket lokal tercipta dan melayani streaming byte raw PTY.
  - Unit test lulus 100%.

### S66-T2: cuan-server WebSocket Proxy ke Runner PTY & Deploy Resilience Gate
- **Branch:** `feature/s66-t2-server-pty-proxy`
- **Scope:**
  1. Modifikasi `internal/terminal/handler.go` di `cuan-server`: jika sesi aktif dijalankan oleh `cuan-runner`, proxy-kan koneksi WebSocket klien langsung ke Unix Domain Socket runner.
  2. Implementasikan auto-reconnect resilient: saat `cuan-server` restart, koneksi WebSocket browser otomatis pulih tanpa memutus proses yang sedang berjalan di `cuan-runner`.
  3. Validasi graceful handling saat runner mati atau task selesai: socket ditutup bersih dan state dialihkan ke log playback.
- **DoD:**
  - Endpoint WebSocket `/api/v1/tasks/{id}/terminal` sukses menyalurkan data PTY dua arah dari `cuan-runner`.
  - Simulasi restart `cuan-server` membuktikan proses agen di `cuan-runner` tidak terbunuh dan streaming pulih saat server kembali online.

### S66-T3: Frontend Pure Live PTY Terminal (xterm.js) & Anti-Spam Customer Chat Isolation
- **Branch:** `feature/s66-t3-frontend-pty-and-chat-hygiene`
- **Scope:**
