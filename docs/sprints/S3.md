## Sprint goal dan demo outcome

### Sprint Goal
Membangun Universal App Deployer dan Studio Runtime mandiri (*self-hosted digital project studio*) dengan intake upload ZIP (anti-ZipSlip) dan Git clone, auto-detection stack runtime (PHP/WordPress, Node.js, Static HTML), alokasi dynamic port management pool terisolasi (range 9000–9999), routing dynamic virtual host via Caddy reverse proxy dengan subdomain otomatis `{slug}.cuan.dojo.cc` dan auto TLS, Studio Dashboard interaktif (`/studio`), toggle konfigurasi `APP_MODE` (`marketing` vs `studio`), serta pengujian E2E staging dan release gate dengan 100% retensi data Sprint 1 dan Sprint 2.

### Demo Outcome
1. Pengguna membuka Studio Dashboard di `/studio` (atau langsung di root `/` saat `APP_MODE=studio`), lalu mengeklik "Deploy New Project".
2. Pengguna mengunggah arsip berkas ZIP script web (atau memasukkan URL Git repo).
3. Intake engine mengekstrak arsip secara aman di direktori terisolasi `data/deployments/<id>/`, memverifikasi tidak ada path traversal berbahaya (anti-ZipSlip), dan secara otomatis mendeteksi stack:
   - Terdeteksi `index.php` / `wp-config.php` → runtime PHP.
   - Terdeteksi `package.json` → runtime Node.js.
   - Terdeteksi `index.html` → runtime Static HTML.
4. Process Runner mengalokasikan port unik bebas konflik dari dynamic port pool (9000–9999) dan menyalakan proses aplikasi di latar belakang.
5. Caddy reverse proxy secara otomatis meregistrasikan rute virtual host dinamis: subdomain `{slug}.cuan.dojo.cc` langsung mem-proxy request HTTPS ke port internal proses aplikasi.
6. Pengguna membuka live URL subdomain `{slug}.cuan.dojo.cc` dan aplikasi web berhasil berjalan mulus.
7. Pengguna mengendalikan proses via drawer kontrol Studio Dashboard (Start, Stop, Restart) dan mengamati live streaming log (stdout/stderr) secara real-time.
8. Pergantian konfigurasi `APP_MODE=marketing` menyajikan Landing Page PAS & Sponsorship v1.0, sedangkan `APP_MODE=studio` langsung menyajikan Studio Dashboard bagi pemilik Cuan mandiri.

## Target pengguna dan nilai produk

### Persona Target Market
1. **Solo Developer & Indie Hacker:** Membutuhkan platform deploy mandiri yang tidak rumit, tidak memerlukan konfigurasi server/terminal yang berbelit-belit, dan dapat menjalankan berbagai proyek kecil hingga menengah dengan instan.
2. **Kolektor & Pembeli Script Digital (WordPress, CodeCanyon, GitHub repos):** Membeli atau mengunduh script web dan web tools, namun sering terbentur kerumitan setup cPanel, Dockerfile, Nginx config, dan SSL.
3. **Founding Backers & Sponsor Cuan:** Menantikan realisasi janji fungsionalitas utama (*core utility product*) yang telah diperkenalkan sejak Landing Page PAS Sprint 2.

### Pertimbangan Kepuasan Target Market (DoD Focus)
- **Zero-Friction Intake:** Pengguna cukup drag-and-drop file ZIP atau paste link Git; stack terdeteksi otomatis tanpa perlu membuat konfigurasi rumit secara manual.
- **Keamanan Ketat (Anti-ZipSlip Defense):** Mencegah eksploitasi path traversal dari file ZIP berbahaya yang berpotensi menimpa file sistem atau merusak aplikasi induk Cuan.
- **Subdomain Otomatis Tanpa Restart Proxy:** Pengguna mendapatkan subdomain langsung (`{slug}.cuan.dojo.cc`) dengan HTTPS otomatis dalam hitungan detik tanpa mengganggu request aplikasi lain yang sedang berjalan.
- **Kemandirian Lingkungan (App Mode Switcher):** Memberikan fleksibilitas bagi pemilik Cuan untuk menjalankan mode publik/marketing atau mode digital studio murni.

## Fondasi teknis dan arsitektur

- **Backend:** Go (Golang) menggunakan `net/http` dan router `chi/v5`.
- **Database:** PostgreSQL dengan migrasi berversi non-destructive (`000008_deployer.up.sql`), menjamin 100% kompatibilitas data Sprint 1 (`owners`, `projects`, `tasks`, `task_attempts`, `agent_logs`) dan Sprint 2 (`sponsorship_batches`, `sponsors`, `sponsorship_orders`, `waiting_list_leads`, `sponsorship_activities`).
- **Arsitektur Modular DeployDriver:**
  - Desain interface `DeployDriver` di `internal/deployer/driver.go` memisahkan logika orkestrasi dari target eksekusi fisik.
  - Implementasi `LocalDriver` pada Sprint 3 mengeksekusi aplikasi secara co-located di mesin yang sama dengan Cuan.
  - Menyiapkan ekstensi `SSHDriver` pada Sprint 4 untuk menghubungkan remote VPS pengguna (*Bring Your Own Server / BYOS*).
- **Frontend:** React + Vite + TypeScript + Tailwind CSS + shadcn/ui di `web/src/components/studio/`.
- **Reverse Proxy:** Caddy dengan modul dynamic virtual host routing menuju port internal runner.
- **Domain Base:** Konfigurasi dinamis via `BASE_DOMAIN=cuan.dojo.cc`.

## Infrastruktur, routing, dan staging gate

1. **Host & Port:**
   - Stable: Port `8080` (reverse proxy Caddy HTTPS).
   - Staging: Port `8081` (Compose project terisolasi, database terpisah).
   - Dynamic Sandbox Port Pool: Range `9000` s/d `9999` dialokasikan secara atomic oleh runner.
2. **Reverse Proxy (Caddy):**
   - Routing default: root `/` mengarah ke Landing Page PAS jika `APP_MODE=marketing`, atau Studio Dashboard jika `APP_MODE=studio`.
   - Routing `/studio`: Studio Dashboard manajemen aplikasi.
   - Routing `/api/deployments/*`: API manajemen lifecycle deployment dan streaming logs.
   - Dynamic Host Routing: `{slug}.cuan.dojo.cc` mengarah secara transparan ke `127.0.0.1:{internal_port}`.
   - Friendly Fallback: Menampilkan halaman status informatif jika aplikasi sedang booting atau dinonaktifkan (502/503 graceful page).
3. **Data Retention Gate:**
   - Migrasi database `000008_deployer.up.sql` murni aditif dan tidak mengutak-atik tabel Sprint 1 & Sprint 2.
   - Verifikasi rollback migrasi `000008_deployer.down.sql` wajib bersih tanpa menghapus data tabel lainnya.

## Out of scope eksplisit

- Orkestrasi multi-node Bring Your Own Server (BYOS) via SSH remote VPS (disiapkan untuk Sprint 4).
- Engine container Docker/Podman atau Kubernetes orchestration di host pengguna (Sprint 3 berfokus pada co-located process isolation).
- Otomasi pembuatan database multi-tenant terpisah (MySQL/PostgreSQL) per project pengguna (konfigurasi database via manual env vars di Sprint 3).
- Custom domain pribadi pengguna selain subdomain berbasis `BASE_DOMAIN` (`*.cuan.dojo.cc`).
- Webhook trigger otomatis dari GitHub (CI/CD auto-deploy on push) untuk Sprint 3 (manual trigger/upload di Studio Dashboard).

## Risiko dan respons

| Risiko | Dampak | Respons / Mitigasi |
| --- | --- | --- |
| Arsip ZIP mengandung payload path traversal ZipSlip (`../../etc/passwd`) | Potensi kebocoran atau penimpaan berkas sistem host | Sanitasi jalur ketat: verifikasi `filepath.Clean`, tolak path berawalan `/`, `\`, atau mengandung `..`, batasi ekstraksi hanya dalam direktori target |
| Konflik port lokal antar deployment pengguna (port collision) | Proses gagal start atau membajak port service lain | Atomic port lease allocator pada rentang 9000–9999 dengan pengecekan ketersediaan socket riil sebelum binding |
| Proses script pengguna mogok (*crash*) atau mengalami kebocoran memori (*memory leak*) | Mengganggu performa host Cuan | Pencatatan PID, isolasi proses subprocess, health check periodik, dan kemampuan force-stop via dashboard |
| Service Caddy mengalami restart dan konfigurasi rute hilang | Subdomain project tidak dapat diakses | Persistence state rute di database dan rekonsiliasi dinamis saat Cuan boot |
| Migrasi database mengganggu tabel eksisting Sprint 1 & 2 | Data pengguna, task, atau sponsorship hilang | Skema murni aditif (`CREATE TABLE IF NOT EXISTS`), foreign key terisolasi (`ON DELETE CASCADE`), verifikasi rollback bersih |
