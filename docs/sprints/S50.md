## Target Market Fit & Nilai Tambah UMKM

- **Target Market**: Pemilik usaha mikro, kecil, dan menengah (UMKM), solopreneur, admin toko online, dan manajer operasional bisnis di Indonesia yang ingin memanfaatkan kecerdasan buatan untuk otomatisasi customer service, pembukuan, dan manajemen stok, namun menghadapi hambatan teknis dan dilema biaya langganan ganda.
- **Nilai Tambah & Alasan Target Market Menyukai Solusi Ini**:
  1. **Zero Double-Cost (Bebas Biaya Dobel)**:
     Banyak pengusaha UMKM telah memiliki akun langganan bulanan seperti ChatGPT Plus ($20/bln) atau Claude Pro ($20/bln) untuk kebutuhan harian. Selama ini, platform SaaS lain memaksa mereka membayar biaya token API per transaksi yang mahal. Dengan *Subscription Harness Adapter*, Cuan mengizinkan pengguna memanfaatkan hak akses langganan yang sudah dibayar tersebut tanpa mengeluarkan biaya token tambahan.
  2. **Pilihan Model Super Hemat via Universal BYOK (Zero-Markup Economy)**:
     Bagi UMKM yang ingin volume percakapan tinggi dengan biaya termurah, mereka cukup memasukkan API Key DeepSeek (V3/R1) atau Groq. Model DeepSeek menawarkan efisiensi biaya hingga 90% lebih murah dibandingkan model komersial tertutup, memungkinkan UMKM melayani ribuan chat pelanggan dengan anggaran minim.
  3. **Zero-Dependency & Zero-Developer Friction (Tanpa Buka Terminal)**:
     Pengguna UMKM adalah non-developer. Mereka tidak mengerti cara membuka terminal SSH, menginstal Python pip, npm, atau menyunting file JSON/YAML. Seluruh instalasi binary harness (`claude`, `codex`, `agy`) dilakukan dengan 1-klik di browser langsung ke direktori user-space `~/.local/bin`. Backend BYOK dibangun murni dengan Go standard library tanpa perlu menginstal runtime tambahan di server.
  4. **Keamanan & Privasi Tingkat Tinggi (Zero Credential Leaks)**:
     API key dan kredensial pengguna dienkripsi kuat menggunakan AES-256-GCM. Kredensial tidak pernah ditampilkan utuh di layar setelah disimpan, tidak pernah dicatat di server log, dan hanya didekripsi saat eksekusi panggilan aman ke API resmi provider.

## Risks & Mitigations

1. **Risk: Perbedaan Wire Protocol Antara Berbagai AI Provider (OpenAI vs Anthropic Messages vs Ollama)**
   - *Dampak:* Format request payload, streaming chunks (SSE), token usage reporting, dan struktur error berbeda antar vendor, berpotensi memicu kegagalan parsing respon pada agen.
   - *Mitigasi:* Mengembangkan lapisan abstraksi internal terpadu di Go (`AIProviderRequest` dan `AIProviderResponse`) dengan adapter terisolasi per keluarga protocol (OpenAI-compatible adapter untuk DeepSeek, Grok, OpenRouter, Groq; dan Anthropic Messages adapter). Seluruh parsing respon divalidasi dengan unit tests komprehensif.
2. **Risk: Kebocoran Kredensial API Key Pengguna (Credential Leaks)**
   - *Dampak:* Kredensial API key rahasia yang dimasukkan pengguna rentan terbaca dalam database plaintext, log server, atau terekspos kembali secara utuh ke antarmuka web.
   - *Mitigasi:* Kredensial dienkripsi simetris menggunakan AES-256-GCM sebelum disimpan ke penyimpanan persisten. Saat dikirim kembali ke frontend, nilai key selalu di-mask (`sk-...xxxx`). Di sisi backend, middleware logging dan error handler dikonfigurasi untuk menyaring serta mereplace pola token dengan `[REDACTED]`.
3. **Risk: Ketergantungan Eksekusi CLI Harness Resmi yang Menggantung (Hanging Process / Lockup)**
   - *Dampak:* Eksekusi headless CLI pihak ketiga (`claude`, `codex`, `agy`) dapat terhenti atau menunggu input interaktif (stdin prompt) yang membekukan thread server.
   - *Mitigasi:* Bungkus setiap eksekusi CLI dengan `exec.CommandContext` dengan batas timeout ketat (misal 30–60 detik). Jalankan selalu dengan flag non-interactive (`--batch` atau `--non-interactive`), stdin ditutup (`/dev/null`), dan buffer output terisolasi.
4. **Risk: Kegagalan Akses atau Rate Limit pada Provider BYOK Pihak Ketiga**
   - *Dampak:* Server provider BYOK (seperti lonjakan trafik DeepSeek atau saldo habis) dapat menyebabkan respon agen gagal di sisi pengguna akhir.
   - *Mitigasi:* Implementasikan pengujian latensi instan di UI agar pengguna dapat memvalidasi status koneksi sebelum mengaktifkan model. Sediakan pesan kesalahan yang informatif dalam Bahasa Indonesia dan graceful fallback ke model default sistem jika provider BYOK mengalami kegagalan berulang.
