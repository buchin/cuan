## Sprint goal dan demo outcome

### Sprint Goal
Membangun ekosistem Batch Campaigns Engine dan Multi-Project Fan-Out Execution pada Cuan: mengimplementasikan skema database migrasi 000013 (`batch_campaigns`) dengan jaminan 100% data retention Sprint 1–7, membangun mesin pemecah kampanye induk menjadi subtasks proyek (`Fan-Out Decompiler Engine`), worker pool eksekusi paralel terisolasi per proyek (`Multi-Project Isolated Runner Engine`), agregator status tersentralisasi (`Centralized Rollup Aggregator`), pemancar progress live (`SSE Streaming Engine`), antarmuka Campaign Studio lengkap dengan Multi-Project Selector di Web UI, serta pembuktian nyata melalui simulasi otomatis rollout massal pada 10 proyek WordPress/AdSense di staging hingga peluncuran produksi stabil di `cuan.dojo.cc`.

### Demo Outcome
1. Pengguna membuka Studio Dashboard dan mengakses menu baru "Campaigns" (`/studio/campaigns`).
2. Pengguna membuat kampanye batch baru dengan memilih target proyek berbasis kriteria tags (contoh: `tag:wordpress`, `tag:adsense`) atau multi-seleksi eksplisit, memasukkan skrip template (payload), dan mendefinisikan kriteria DoD tugas anak.
3. Decompiler Engine secara otomatis memecah kampanye induk menjadi subtasks `project_tasks` yang terikat pada masing-masing proyek target (`parent_task_id`, `batch_id`, `tags`).
4. Runner worker pool mengeksekusi subtasks secara paralel dan terisolasi tanpa memblokir sistem utama atau saling mengganggu antar-proyek.
5. Rollup Aggregator menghitung metrik live (pending, running, completed, review, failed, success percentage) dan menyiarkan pembaruan real-time via Server-Sent Events (SSE) langsung ke tampilan progress bar di browser pengguna.
6. Staging E2E drill membuktikan simulasi kampanye massal 10 situs WordPress berhasil dieksekusi 10/10 sukses, diikuti rilis produksi di `cuan.dojo.cc` dengan verifikasi 100% data retention Sprint 1–7 utuh.

## Target pengguna dan nilai produk

### Persona Target Market
1. **Multi-Project Operators & Agency Leads:** Mengelola puluhan situs klien (e.g. niche affiliate/AdSense, WP multisite). Membutuhkan cara cepat untuk melakukan perubahan konfigurasi, pembaruan skrip analitik/iklan, atau patch keamanan secara massal tanpa harus membuka dan mengedit proyek satu per satu.
2. **Solo Developer & Indie Hackers:** Mengoperasikan portfolio aplikasi digital secara mandiri. Memerlukan otomatisasi rollout yang hemat waktu, aman dari kegagalan parsial (*isolated blast radius*), dan transparan via live dashboard.
3. **AI-Assisted Operations:** Agen otonom dapat memicu batch campaign berbasis kriteria tag sistemik dan memantau penyelesaian subtask secara terstruktur.

### Pertimbangan Kepuasan Target Market (DoD Focus)
- **Zero-Friction Mass Operations:** Cukup 1 klik untuk memicu perubahan terarah ke puluhan repositori/proyek yang sesuai kriteria tags.
- **Fail-Safe Isolated Execution:** Eksekusi worker pool per proyek berjalan mandiri; kegagalan pada 1 proyek tidak menghentikan atau merusak proses di proyek lainnya.
- **Real-Time Visibility:** Pengguna melihat progress bar agregat dan log eksekusi langsung via SSE tanpa perlu merefresh halaman berulang kali.
- **Strict Data Retention (100% Data Integrity):** Seluruh skema database bersifat aditif non-destruktif; seluruh data dari Sprint 1 hingga Sprint 7 (owners, projects, tasks, sponsors, deployments, servers, domains, observability, studio rooms/messages/tasks) tetap 100% utuh.

## Fondasi teknis dan arsitektur

- **Backend:** Go (Golang) menggunakan router `chi/v5` dan `database/sql` PostgreSQL 16.
- **Database Schema (`migrations/000013_batch_campaigns.up.sql`):**
  - Tabel `batch_campaigns`:
    - `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`
    - `title VARCHAR(255) NOT NULL`
    - `description TEXT NOT NULL DEFAULT ''`
    - `template_payload JSONB NOT NULL DEFAULT '{}'::jsonb`
    - `target_criteria JSONB NOT NULL DEFAULT '{}'::jsonb`
    - `status VARCHAR(50) NOT NULL DEFAULT 'draft'`
    - `created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW()`
    - `updated_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW()`
    - Indeks btree pada `status`, `created_at`, `title`, serta indeks GIN pada `template_payload` dan `target_criteria`.
- **Repository Layer (`internal/db/batch_campaign.go` & `internal/db/db.go`):**
  - Entitas `BatchCampaign`, DTO `CreateBatchCampaignInput`, `UpdateBatchCampaignInput`, `BatchCampaignFilter`, dan `BatchCampaignDTO`.
  - Interface `BatchCampaignRepository` dengan implementasi `SQLBatchCampaignRepository` dan thread-safe `MemoryBatchCampaignRepository`.
  - Registrasi terpusat pada container `db.Repositories` dan `server.Server`.
- **Decompiler & Runner Engine (`internal/campaign/`):**
  - `DecompilerEngine`: Resolver kriteria tags dan generator subtasks `project_tasks`.
  - `IsolatedRunnerPool`: Worker pool terkontrol (default 5 worker paralel) dengan graceful cancellation dan panic recovery.
  - `RollupAggregator`: Komputasi agregat progress dan event publisher SSE (`campaign.progress`, `task.status_changed`, `campaign.completed`).
- **Frontend Campaign Studio:** React + TypeScript + Tailwind CSS + shadcn/ui di `web/src/components/studio/` (`BatchCampaignModal.tsx`, `CampaignDashboardView.tsx`, `CampaignDetailView.tsx`).

## Risiko dan respons

| Risiko | Dampak | Respons / Mitigasi |
| --- | --- | --- |
| Lonjakan load sistem saat menjalankan puluhan worker paralel | CPU/RAM spike pada VPS host | Pembatasan worker pool konkurensi (default limit 5 paralel) dengan antrean teratur |
| Kegagalan eksekusi pada salah satu proyek target (misal network error atau syntax error) | Kampanye batch berhenti di tengah jalan | Isolasi per proyek (isolated blast radius): kegagalan 1 proyek hanya menandai subtask tersebut `failed`, sementara subtask lain tetap berjalan |
| Banyak koneksi SSE terbuka secara bersamaan | File descriptor leak | Heartbeat interval 15s dan otomatis cleanup listener saat `r.Context().Done()` terpicu |
