## Spesifikasi Teknis Konfigurasi & Protokol

### 1. Streaming Pipe Architecture & Buffer Elimination
- **Mekanisme Lama:** Menampung `stdout` dan `stderr` ke dalam `bytes.Buffer` statis dalam memori hingga proses agen selesai atau waktu habis, baru kemudian menulis log kumulatif ke basis data/file.
- **Mekanisme Baru:** Menggunakan `io.Pipe()` ganda atau pemindai baris terarah (`bufio.Scanner` / chunk reader) di `internal/agent/agy_adapter.go`. Setiap baris atau potongan data teks yang keluar dari proses diekspos secara seketika (*line-by-line emission*) ke callback pendengar di daemon `cuan-runner`.
- **Ketahanan Aliran:** Menggunakan buffer internal sirkular terikat (*bounded ring-buffer*) untuk membatasi konsumsi memori saat lonjakan keluaran teks cepat terjadi, mencegah kebocoran memori (*memory leak*).

### 2. Endpoint Streaming Logs `/api/v1/runner/attempts/{id}/logs`
- Mendukung pengambilan log aktif secara bertahap menggunakan parameter offset (`?offset=N`) atau streaming HTTP chunked berkinerja tinggi.
- Mengembalikan potongan teks log terbaru yang belum diterima klien tanpa membaca ulang seluruh berkas log dari awal.
- Mengirimkan sinyal status penyelesaian (`is_final: true`) saat attempt selesai dieksekusi.

### 3. Protokol Interactive Steering
- Endpoint `/api/v1/runner/attempts/{id}/steer` menerima payload JSON `{"prompt": "instruksi tambahan", "author": "user"}`.
- Daemon `cuan-runner` menyalurkan teks arahan langsung ke pipa masukan standar (`stdin`) dari proses agen yang sedang aktif.
- Apabila proses agen tidak mendukung interaktivitas stdin, respons *graceful fallback* dikembalikan dengan mencatat arahan sebagai pesan tindak lanjut berikutnya (*queued follow-up prompt*).

### 4. Matriks Alokasi Waktu Timeout & Grace Period

| Layer Eksekusi | Parameter / Skenario | Konfigurasi Default | Toleransi / Grace | Rationale Bisnis & Pengguna |
|----------------|----------------------|---------------------|-------------------|-----------------------------|

| **Agent Chat CLI** | Direct Coordinator Recovery | **120s (2 menit)** | - | Toleransi stabilisasi parsing koordinasi multi-agent. |
| **Agent Chat CLI** | Chat Lifecycle Context | **10 menit** | - | Context HTTP server terjaga penuh selama putaran instruksi panjang. |

## Risiko, Batasan & Mitigasi

1. **Risk: Deadlock atau Buffer Exhaustion pada Goroutine Streaming Pipe**:
   - *Dampak:* Pembacaan stdout/stderr agen yang tersendat pada pipa asinkron dapat memblokir proses agen utama.
   - *Mitigasi:* Menggunakan saluran pipa dengan pembacaan asinkron non-blocking, dilengkapi *bounded buffer* dan *timeout context* pada setiap operasi emisi chunk/baris.
2. **Risk: Beban Lonjakan HTTP Streaming Log yang Terlalu Rapat**:
   - *Dampak:* Frekuensi polling log yang terlalu agresif dari banyak tab browser dapat membebani antarmuka API server backend.
   - *Mitigasi:* Menggunakan skema offset incremental (`?offset=N`) yang hanya mengembalikan delta byte baru dan interval polling adaptif (1–2s saat aktif, backoff saat idle).
3. **Risk: Regresi Tata Letak Obrolan Saat Menghapus TaskProgressBanner**:
   - *Dampak:* Penghapusan komponen banner dan spasi `pt-14` berpotensi menimbulkan pergeseran posisi pesan atau pemotongan konten pada resolusi layar tertentu.
   - *Mitigasi:* Menggunakan uji visual targeted dan pengujian Vitest pada `InboxView.tsx` untuk memastikan kontainer scroll pesan menempati tinggi penuh (*flex-1 overflow-y-auto*) secara proporsional.

- **Infrastruktur Full-Duplex WebSockets / Socket.IO Kompleks**: Streaming log dan steering tetap mengandalkan HTTP chunked/REST streaming dan endpoint terstandar yang lebih ringan, tahan banting pada jaringan seluler, dan ramah reverse proxy Caddy/Nginx.
