# Cuan Sprint 27 — Multi-provider agent, auto-retry & agent picker per task

## Rekomendasi untuk PO (diajukan SM)

**Rekomendasi:** Approve scope S27 dibawah — dampak bisnis terbesar (pengguna tidak kena limit satu provider, task tidak gagal karena kuota), effort relatif kecil untuk auto-retry + agent picker, urgensi tinggi karena S26 baru saja ditutup dan pengguna mulai merasakan keterbatasan satu provider `agy`.

**Alternatif:** Hanya auto-retry default + agent picker per task (undaikan provider selain `agy` ke sprint berikutnya) — effort lebih kecil tapi pengguna masih terkunci satu provider.

**Alasan:** Auto-retry dan agent picker langsung mengatasi gangguan harian tanpa menambahkan provider baru. Provider baru (CommandCode) dapat diambil setelah basis auto-retry dan agent picker stabil.

---

## Tujuan sprint

Pengguna non-developer dapat menugaskan pekerjaan melalui studio/inbox tanpa takut task gagal hanya karena satu agent/kuota terkena limit, dan memiliki opsi memilih agent yang tersedia atau biarkan sistem memilih otomatis.

## Definisi Selesai (DoD) setiap task

**T1 — Auto-retry default**
- Saat task diterima dan agent yang dipilih kena limit, sistem mencoba agent lain yang verified & available secara otomatis.
- Maksimal 3 kali percobaan ulang dalam satu view, kemudian tampilkan pesan error informatif kepada user.
- Tidak ada duplikasi pesan user atau eksekusi CLI yang sama saat retry/refresh (idempoten via request UUID/hash).
- Targeted test terarah (tidak full suite) bukti retry aman dan tidak duplikat.
- Dokumentasi singkat di `docs/` mengenai perilaku auto-retry.

**T2 — Agent picker per task**
- UI studio/inbox menampilkan daftar agent dengan status (verified / quota_limited / login_required / unavailable).
- Opsi "Auto (pilih terbaik)" sebagai default; user bisa override memilih agent spesifik yang available.
- Agent yang `quota_limited` atau `login_required` tidak dapat dipilih untuk eksekusi baru.
- Build frontend lolos (Vite/TypeScript), tidak ada warning baru yang melanggar standar repo.

**T3 — CommandCode sebagai provider (subscription + custom BYOK)**
- Frontend StudioView & TeamView dapat memilih CommandCode selain Google (`agy`), dengan dua mode koneksi: subscription connect dan custom provider BYOK.
- Backend `auth-status` / `auth-init` / `connectCLI` mendukung CommandCode (keduanya) tanpa return "not verified by this integration".
- `executeInboxCLI` perlu memeriksa biner CommandCode sebelum menawarkannya sebagai opsi provider.
- Custom provider BYOK menyimpan API key user di `ProviderAccount` terenkripsi (bukan kredensial Fural/developer), sesuai prinsip AGENTS.md.
- Tidak ada kredensial Fural/developer yang dibagikan sebagai kredensial user (prinsip AGENTS.md).
- **Vision per-model:** tidak semua model punya vision. Saat model dipilih, sistem cek apakah model tersebut support vision sebelum mengizinkan input gambar; jika tidak, tampilkan pesan informatif dan batalkan input gambar untuk model tersebut.
- Dokumentasi di `docs/` mengenai cara menambah provider CLI baru, batasan vision per-model, dan keterbatasan lainnya.

## Risiko & batasan

- Auto-retry hanya akan berhasil jika ada ≥1 agent lain yang verified & available. Jika semua kena limit, tetap tampilkan error informatif (jangan sembunyikan).
- Provider non-agy memerlukan CLI terinstall di environment server; verifikasi biner sebelum menyorokkan opsi tersebut ke user.
- Jangan mengubah skema produksi atau melakukan migration destruktif. Hanya perubahan tambitif jika benar-benar diperlukan.
- S26.3 masih terblokir gateway 504 di publisher staging (batasan infrastruktur) — tidak mempengaruhi S27 secara langsung tapi catat sebagai batasan publikasi staging.
