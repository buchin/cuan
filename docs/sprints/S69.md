## 1. Ringkasan Eksekutif & Sasaran Sprint 69

Sprint 69 melakukan refactor fundamental pada arsitektur agen dan tim agar 100% selaras dengan kebutuhan **target market non-developer** (UMKM, bisnis, profesional) sesuai prinsip *Zero Cognitive Fatigue* (Things 3 & Bear Notes):

1. **Single Unified Assistant (Menghapus Fragmentasi Nickname):**
   - Menghapus nickname agen teknis (`@dev`, `@sm`, `@qa`, `@architect`) dari antarmuka pengguna publik.
   - Pengguna hanya berinteraksi dengan satu asisten terpadu: **`Cuan`** (atau nama kustom yang disetel pengguna, misal: *Asisten Toko*, *Jarvis*).
   - Di balik layar, sub-agents teknis tetap bekerja secara otonom tanpa membebani mental model pengguna.

2. **Autonomous Brain Cluster & Provider-Agnostic Dispatcher:**
   - Tidak ada asumsi atau pemaksaan bahwa pengguna harus menggunakan Google atau brand AI tertentu. Pengguna bebas menghubungkan akun apa saja (OpenAI, Anthropic Claude, DeepSeek, Groq, xAI Grok, OpenRouter, Ollama lokal).
   - Seluruh akun AI terhubung diperlakukan sebagai **peer worker nodes** dalam satu cluster server komputasi otak.
   - Sistem melakukan *load balancing* cerdas, *auto-failover* tanpa hambatan saat rate-limit/token habis, dan *smart vision routing* saat pengguna mengunggah gambar/struk.
   - **Menu `AI Providers` dihapus total dari navigasi & pengaturan**, karena fungsi penyambungan akun AI disatukan langsung di bawah kartu Asisten.

3. **Dedicated & Pure Human "Team" Management:**
   - Memisahkan manajemen tim staf manusia dari konfigurasi AI.
   - Menu **Team** berdiri sendiri murni untuk kolaborasi manusia: daftar staf, status undangan, dan peran (Owner / Staf).
   - Bebas 100% dari istilah teknis AI, API key, atau bot.

## 2. Backlog Task Sprint 69

### S69-T1: Provider-Agnostic Brain Cluster Dispatcher (Backend & Shared Logic)
- **Scope:**
  1. Pastikan router AI di backend memperlakukan akun-akun AI terdaftar sebagai kumpulan worker nodes tanpa bias provider utama/cadangan.
  2. Implementasikan failover dan vision capability check secara transparan:
     - Request teks biasa: round-robin / least-loaded dispatch ke node yang ready.
     - Request multimodal / gambar: otomatis rute ke node yang mendukung vision (`isModelVisionCapable`).
     - Error handling (429 / 5xx / Quota Exceeded): seketika failover ke node aktif berikutnya.
- **DoD:**
  - Request berhasil dieksekusi tanpa bergantung pada satu provider tertentu.
  - Failover transparan saat satu node down / limit.
  - Unit test router/dispatcher lulus 100%.
