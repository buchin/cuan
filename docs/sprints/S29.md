# Cuan Sprint 29 — Scrum Master Semantic Intent & Tooling Architecture + Inbox Mark All Read

## Rekomendasi untuk PO (diajukan SM)

**Rekomendasi:** Approve scope S29 di bawah ini — menyelesaikan akar masalah kegagalan interaksi Scrum Master pada konsultasi arsitektur dan inspeksi kode (menghapus over-eager approval & delegation rules, mengganti pola keyword regex dengan *Semantic Intent Contract* berbasis peran yang siap untuk rilis Open Source internasional), melengkapi ekosistem *read-only code inspection tools* bagi SM di dalam chat, serta mengimplementasikan fitur *Mark All as Read* (UI & API batch) di Inbox Cuan secara tuntas dan terverifikasi di produksi.

**Alternatif:** Hanya memperbaiki teks prompt tanpa menambahkan dukungan API batch dan fitur UI *Mark All as Read* — effort lebih kecil tetapi kebutuhan pengguna di Inbox Cuan tetap belum terwujud dan SM masih berisiko lambat saat memeriksa komponen UI.

**Alasan:** Kejadian di room `8baa3876-01dd-44ac-a030-4d2e7836482b` membuktikan bahwa pembatasan kaku pada prompt koordinator (`MANDATORY APPROVAL ACTION` dan *over-eager fallback* ke "Sesi Analisis Mandiri") merusak pengalaman percakapan. SM membutuhkan kebebasan berdiskusi secara eksploratif dalam mode Advisory tanpa dipaksa membuat kartu tiket kerja, didukung kapabilitas navigasi kode/rute yang efisien, serta merealisasikan fitur *Mark All as Read* yang dibutuhkan oleh pengguna.

---

## Tujuan Sprint

1. **Semantic Intent & Prompt Relaxation (OSS & International Ready):**
   Memperbarui kontrak koordinasi SM di `internal/workflow/coordinator.md` dan `internal/server/inbox_coordinator_response.go` agar memisahkan secara tegas antara **Mode Konsultasi/Advisory** (`action: null` untuk tanya-jawab teknis, eksplorasi desain, dan pembacaan kode langsung di chat) dengan **Mode Otorisasi/Eksekusi** (`action: approval` atau `delegation` hanya saat ada perintah kerja eksplisit atau persetujuan lingkup). Menghilangkan aturan kaku pemaksaan kartu approval dan delegasi otomatis background task yang memutus alur chat.
2. **SM In-Chat Code & Component Inspection Tooling:**
   Memperkuat kapabilitas inspeksi kode read-only di dalam chat turn, termasuk panduan pemanfaatan `view_file_outline`, `view_code_item`, katalog rute API, dan inspeksi diff git ringkas agar SM dapat menjawab pertanyaan tata letak dan arsitektur kode secara instan tanpa menciptakan task runner dummy.
3. **Fitur "Mark All as Read" di Inbox Cuan (UI & API):**
   Menambahkan dukungan mutasi batch `mark_all: true` pada endpoint `PATCH /api/v1/item-preferences?kind=conversation` di backend, serta menambahkan tombol aksi `CheckCheck` (*Tandai semua dibaca*) pada header filter/sub-panel `web/src/features/inbox/InboxSubPanel.tsx` dengan sinkronisasi state instan dan uji responsif.

## Definisi Selesai (DoD) Setiap Task

### T1 — Semantic Intent Contract & Coordinator Prompt Relaxation
- Di `internal/workflow/coordinator.md` dan `internal/server/inbox_coordinator_response.go`:
  - Ditegaskan pemisahan semantik antara **Mode Advisory/Konsultasi** (pertanyaan arsitektur, opini tata letak, pemeriksaan kode -> `action: null`, tanpa membuat tiket task atau kartu approval paksaan) dan **Mode Direktif/Eksekusi** (perintah kerja jelas atau konfirmasi PO -> kartu `approval` atau aksi `delegation`).
  - Dihapus aturan restriktif `MANDATORY APPROVAL ACTION` yang memaksa kartu approval pada setiap saran konseptual.
  - Dihapus aturan over-eager yang memaksa mendelegasikan "Sesi Analisis Mandiri" ke runner background saat PO hanya meminta *"cek kodenya"* / *"check the code"*.
  - SM diinstruksikan untuk menggunakan kuota *read-only tool calls* (hingga 12 calls) secara maksimal untuk membaca file dan menjawab langsung di chat.
  - Penanganan pasca-pembatalan task: SM tidak boleh mengeluarkan pesan pasif buntu (*dead-end*), melainkan proaktif merangkum konteks yang sudah diketahui dan mengembalikan inisiatif ke PO.
- Targeted unit test untuk coordinator prompt & response parsing di `internal/server/` lulus 100%.

### T2 — Batch Mark All as Read API Backend (`item-preferences`)
- Endpoint `PATCH /api/v1/item-preferences?kind=conversation` pada `internal/server/item_preferences.go` mendukung parameter atau payload `all: true` / `mark_all_read: true`.
- Mutasi batch memperbarui `read_at` untuk seluruh percakapan aktif yang belum dibaca milik owner terkait secara atomik dalam satu request.
- Targeted unit tests untuk `item_preferences.go` dan `chat_handlers.go` terkait unread status lulus 100%.

### T3 — Inbox Sub-Panel UI Mark All Read Button & State Sync
- Pada `web/src/features/inbox/InboxSubPanel.tsx`:
  - Ditambahkan tombol aksi "Tandai semua dibaca" (menggunakan ikon `CheckCheck` dari Lucide) pada header sub-panel (berdampingan dengan tab filter / tombol Archive atau di action menu).
  - Tombol dilengkapi tooltip dan label aksesibilitas (`aria-label`) multi-bahasa via `t('Mark all as read')`.
  - Tombol hanya aktif/muncul ketika terdapat percakapan yang belum dibaca (`unread_count > 0`).
  - Mengklik tombol memicu mutasi batch ke backend dan seketika mengosongkan badge counter unread di navbar dan daftar chat secara optimistik tanpa reload halaman.
- Hook `useArchivedItems.tsx` diperbarui dengan fungsi `markAllRead()`.
- Pengujian unit frontend (`npm test --prefix web`) dan build produksi TypeScript/Vite lulus 100%.
- Deploy ke produksi `https://cuan.dojo.cc` dan verifikasi live smoke test.

## Risiko & Batasan

- **Risiko:** Perubahan prompt koordinator dapat memengaruhi format JSON output jika tidak divalidasi dengan schema.
  - *Mitigasi:* Pertahankan schema JSON `inboxCoordinatorSchema` yang ketat dan jalankan test validasi decoding di `internal/server/inbox_coordinator_response_test.go`.
- **Batasan:** Tidak ada migrasi skema database baru (tetap menggunakan skema 25; data preferensi tersimpan aman di `.items.json` per owner).
