## Outcome Sprint & Kesepakatan PO

**Outcome:** Menghadirkan kapabilitas *Confidence Scoring*, *Smart Auto-Approval Engine*, dan *Visual Memory Quota Tracking* (Hermes-style) pada sistem Dynamic Taste Cuan. Sistem kini mampu mengukur tingkat keyakinan (confidence score 0.0 – 1.0 / 0% – 100%) terhadap setiap kandidat preferensi yang diekstrak. Kandidat dengan keyakinan tinggi (default >= 80% / 0.80) secara cerdas dipromosikan otomatis ke memori aktif (*auto-approved*) selama kuota kategori belum penuh (< 15 butir), dengan guardrail pengaman 1-Click "Undo" (Batalkan) dan kontrol kuota transparan bagi pengguna non-developer (UMKM dan kreator solo).

**Kesepakatan & Arahan PO (diajukan SM, disetujui PO):**
1. **Confidence Scoring Engine**: Kandidat hasil ekstraksi refleksi menyertakan skor keyakinan `confidence` (rentang 0.0 hingga 1.0).
2. **Smart Auto-Approval dengan Guardrail Kuota**:
   - Threshold default ditetapkan pada 80% (0.80).
   - Jika skor keyakinan >= 0.80 dan kuota butir pada kategori terkait belum mencapai batas maksimum (kuota < 15 butir), sistem secara otomatis mempromosikan kandidat menjadi active taste dengan metadata `auto_approved: true`.
   - Jika kuota sudah penuh (15 butir) atau skor < 0.80, kandidat tetap berstatus `pending` untuk ditinjau manual oleh pengguna.
3. **Safety Guardrail & Kontrol Human-in-the-Loop**:
   - Notifikasi Toast informatif di UI saat auto-approval terjadi, dilengkapi aksi 1-klik "Undo" (Batalkan) untuk mengembalikan item ke pending/dismissed jika pengguna tidak setuju.
   - Pengaturan toggle Auto-Approve on/off dan penyesuaian threshold di antarmuka `AgentMemoryView`.
4. **Hermes-style Visual Memory Quota Tracking**:
   - UI menampilkan visual quota meter persentase dan bar kapasitas memori (misal "8/15 butir Brand Taste terpakai").
   - Penyediaan endpoint backend `/api/v1/taste/quota` untuk metriks pemakaian kuota per kategori.

Agen terhindar dari *context saturation* atau *hallucination* akibat memori yang berlebihan, menjaga performa penalaran agen tetap tajam dan akurat.

## Risks & Mitigations

1. **Risk: False Positives & Kesalahan Auto-Approval**
   - *Dampak:* Agen menyetujui preferensi yang tidak akurat secara otomatis, membingungkan pengguna awam.
   - *Mitigasi:* Menetapkan threshold tinggi (0.80 / 80%), menyertakan metadata `auto_approved: true`, menyediakan notifikasi Toast dengan aksi 1-klik "Undo", serta sakelar toggle switch untuk mematikan auto-approval bila pengguna menginginkan kontrol manual penuh.
2. **Risk: Memory Saturation & Bloat (Context Window Overload)**
   - *Dampak:* Terlalu banyak preferensi yang disetujui otomatis sehingga memenuhi batas token LLM dan menyebabkan halusinasi.
   - *Mitigasi:* Guardrail kuota ketat `MaxTasteItemsPerCategory = 15`. Auto-approval otomatis terhenti saat kuota kategori mencapai 15 butir dan dialihkan menjadi pending review. Visual quota meter (Hermes-style) menampilkan peringatan kapasitas secara real-time.
3. **Risk: Kebingungan Pengguna Non-Developer terhadap Angka Skor**
   - *Dampak:* Pengguna awam merasa terintimidasi oleh angka desimal teknis (*0.85* vs *0.72*).
   - *Mitigasi:* Tampilkan nilai kepercayaan dalam format persentase ramah (`85% Keyakinan`) dengan warna badge intuitif (Hijau untuk keyakinan tinggi, Kuning/Oranye untuk moderat) dan penjelasan singkat.

## Out-of-Scope Eksplisit

- **Tidak Ada Dynamic Threshold per Kategori/Topik**: Ambang batas (threshold) menggunakan single global threshold default 0.80 yang dapat diatur pengguna, bukan threshold berbeda per topik.
- **Tidak Ada Auto-Eviction / Deletion (LRU Memory Pruning)**: Ketika kuota 15 butir penuh, sistem tidak akan menghapus memori lama secara sepihak. Pengguna yang memegang kendali untuk menghapus atau mengganti item preferensi yang ada.
- **Tidak Ada Integrasi Eksternal Vector DB**: Seluruh penyimpanan kuota, kandidat, dan preferensi tetap menggunakan store internal lokal Cuan yang ringan, cepat, dan mandiri tanpa ketergantungan database eksternal.
