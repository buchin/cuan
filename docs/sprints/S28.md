# Cuan Sprint 28 — Deployment Integrity, Lifecycle Auto-Cleanup & Provider Connection UX

## Rekomendasi untuk PO (diajukan SM)

**Rekomendasi:** Approve scope S28 di bawah ini — dampak bisnis terbesar (menutup 100% risiko regresi deploy semu dan proyek terkunci, serta memberikan kendali penuh lifecycle akun AI bagi pengguna non-developer), effort terukur, urgensi sangat tinggi setelah investigasi insiden deployment 25 Oktober 2026.

**Alternatif:** Hanya mengerjakan perbaikan deploy script tanpa perbaikan lifecycle database — effort lebih kecil tetapi risiko antrean task macet di masa depan tetap ada.

**Alasan:** Kejadian regresi deployment membuktikan bahwa Cuan memerlukan gerbang verifikasi SHA di `/healthz`, penegakan restart wajib saat binary berubah, dan pembersihan otomatis state task launch di database agar sistem antrean task berjalan tanpa hambatan.

---

## Tujuan Sprint

Memastikan Cuan memiliki sistem deployment anti-regresi yang memvalidasi commit SHA binary secara end-to-end, menutup seluruh celah kebocoran state task launch di database, serta menyempurnakan antarmuka lifecycle koneksi provider (Subscription & BYOK) di Settings/Team agar pengguna non-developer memiliki kendali penuh tanpa menyentuh terminal.

## Definisi Selesai (DoD) Setiap Task

### T1 — Deployment Integrity & Commit SHA Health Verification
- Endpoint `/healthz` pada `cuan-server` menyertakan `commit_sha` binary aktif (diambil dari build metadata/ldflags atau release manifest).
- Script `scripts/fural-deploy.sh` memvalidasi respon `commit_sha` dari `/healthz` cocok persis dengan `$release_sha` sebelum menyatakan deployment sukses.
- Script `scripts/activate-release.py` menolak opsi `--no-restart` jika berkas binary `bin/cuan-server` mengalami perubahan checksum antara rilis aktif dan target rilis.
- Targeted tests untuk `/healthz` dan skenario deployment lulus 100%.
- Dokumentasi pembaruan prosedur deploy di `docs/operations/` atau `README.md`.

### T2 — Task Launch Lifecycle & State Auto-Cleanup Guard
- Di `internal/task/service.go`, setiap transisi status task ke state terminal (`done`, `cancelled`, `blocked`, `review`) otomatis memanggil pembersihan launch aktif (`FinishTaskLaunches` ke state `stopped`).
- Query `IsProjectActive` di `internal/task/store_db.go` dan `ClaimNextQueuedAttempt` di `internal/runner/store_db.go` secara konsisten memfilter task yang sudah berstatus selesai agar tidak pernah mengunci proyek.
- Targeted unit test (`internal/task` dan `internal/runner`) membuktikan tidak ada row `task_launches` yang tertinggal dalam state `started` setelah task selesai.
- Verifikasi database produksi bersih dari stale launches.

### T3 — Subscription & BYOK Connection Lifecycle UX (Settings/Team)
- Antarmuka Team/Settings menampilkan status koneksi faktual (`connected`, `login_required`, `quota_limited`, `unavailable`) beserta timestamp verifikasi terakhir.
- Tombol aksi jelas dan aman: Reconnect, Retry/Cancel, Disconnect, Hapus, dan Ganti API Key untuk BYOK tanpa instruksi terminal teknis.
- Pencegahan klik ganda (*double-click idempotency*) dan penanganan refresh halaman tanpa kehilangan state.
- Tampilan responsif dan lulus uji aksesibilitas pada layar mobile 360px dan 390px.
- Build frontend (TypeScript/Vite) dan pengujian unit web lulus 100%.
- Panduan penggunaan end-user diperbarui di `docs/guides/provider-cli.md`.

---

## Risiko & Batasan

- **Risiko:** Service restart saat deploy dapat memutus sesi interaktif yang sedang aktif.
  - *Mitigasi:* `activate-release.py` tetap mempertahankan pengecekan pekerjaan aktif yang aman, namun jika binary berubah, restart wajib dilakukan dengan graceful handover atau konfirmasi jeda idle.
- **Batasan:** Tidak ada perubahan skema database baru (tetap menggunakan skema 25 yang sudah ada).
- **Batasan Akun:** Tidak ada kredensial developer/ambient yang dibocorkan ke UI pengguna Cuan.

## Deployment, Migration & Staging Gates

- **Schema Gate:** 25 migrasi terverifikasi aktif, tidak ada migrasi skema yang belum teruji.
